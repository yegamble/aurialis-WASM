## Device-local deployment boundary

The browser build is the v1 release target. The native single binary is a source-built fallback (no prebuilt binaries are published) and the only build that runs Smart Split; see [jobs, uploads and lifetime](#jobs-uploads-and-lifetime) for its single status statement.

The browser-local runtime merged in [PR #16](https://github.com/yegamble/aurialis-WASM/pull/16) at `85aa7cd7556a26e540e40212397624dcf30a16d6`. Exact head `98397c6` passed all 14 CI jobs and GitGuardian in [run 40021166540](https://github.com/yegamble/aurialis-WASM/actions/runs/40021166540), including 107 native and eight static browser cases. Reviewed and merged tracked trees matched; this does not deploy the public site.

The deployment decision keeps every audio byte and processing job on the user’s device. `deviceAudioRequest` maps the existing application contracts to a dedicated disposable Worker on every public origin. The pure `engine-params.ts` mapper is shared by browser transports and the Node-driven compiled parity verifier, without loading browser-only dependencies into that verifier. `internal/browserjobs` compiles the native CDR, mastering, features, Deep, Reference and numeric compiler to Go/WASM. Metadata and transferable audio buffers travel separately; PCM is never encoded as JSON or base64 in the runtime transport. The native executable remains an explicit device-local fallback through its own loopback UI/API. Public pages never probe it or accept a remote native capability override.

One costly browser job runs with one waiting slot. Each request claims its raw source/reference bytes synchronously before enqueueing. That owner remains until the actual run promise settles, including when a waiting caller cancels early; it conservatively overlaps active-job accounting. Byte/frame/memory preflight bounds simultaneous source/canonical Blobs, live PCM, transferred inputs, Go input/output/encoding buffers and returned results. Owned resident-memory scopes add exact retained-cache/intermediate bytes to admission. Their synchronous updates include the active job charge, preventing growth between preflight and buffer cloning; disposal releases only that owner. The existing album cache claims its expected output before each render, retains its artifact-bound scope for downloads and releases it on invalidation, replacement, failure or unmount. A shared download helper keeps a separate temporary owner through object-URL revocation, including after the view releases its cache. Concurrent URLs for one Blob share the temporary owner; allocation/click failures release it and surface in the album status. Cancel terminates the active worker; terminal paths release the private Go heap. Main/worker/Go ABI checks reject stale modules before processing, and constant asset names retain no-store/revalidation behavior. Existing source receipts, DTO validators and latest-intent/revision checks remain authoritative.

Cloudflare serves only static app, WASM and qualified model files. Its Worker allows GET/HEAD, preserves exact native inline-script CSP hashes, COOP/COEP/CORP and WASM MIME, and resolves known dynamic HTML/RSC assets without an unknown-file/API HTML fallback. Model shards must be immutable, hash-verified and at most 16 MiB; trained browser inference remains unavailable. No Container or R2 user-audio path is part of this build. Bundled font/runtime notices remain under `/licenses/`.

## Library source lifecycle

Merged [PR #17](https://github.com/yegamble/aurialis-WASM/pull/17) introduces explicit discovery of the previous app's `aurialis-library-entries-v1/kv` keys. It reads no old values, scripts or preferences, pages at 32 eligible/64 scanned keys, and reports an oversized continuation as incomplete. Selected audio is read from the existing browser `library` directory with fixed encoded key names and `create: false`. A single pending browser-file read remains admitted until it actually settles; five-second waits and caller cancellation do not imply platform preemption.

Supported selected WAVs pass the shared Go CDR import and strict canonical 44-byte geometry check. The import check no longer allocates three source-length PCM validation buffers only to discard them; actual playback still decodes and validates samples. A resident owner covers the selected original, canonical Blob and potential storage copy until durable saving, source rechecks and cleanup settle. Key/size/modification checks detect changes without claiming raw-byte cryptographic identity. Publication uses a fresh ID and default settings, with rollback restricted to that newly staged ID. Every old record and original remains; [compressed recovery](legacy-library.md#when-recovery-cannot-continue) is still unavailable. Four native recovery cases and the complete 12-case static browser suite passed at `9f1c4ce`, after separate closed-artifact removal/restoration for each target. Eight workflow inventories contain 365 same-origin HTTP asset requests and one local Blob read, all GET/HEAD without request bodies, including zero recovery downloads. Exact head `a9e2afa` subsequently passed all 14 CI jobs plus GitGuardian before normal protected merge `59d16f6`. Selected WAV, AIFF, FLAC and MP3 recovery is implemented; unsupported OGG, AAC and M4A files remain stored. Final recovery gates and permanent old-resource retirement remain open.

Home processes selected, dropped or pasted WAV, FLAC and MP3 files sequentially through the existing CDR import. The browser checks finite byte/frame capacity; Go remains authoritative. Cancel or unmount aborts the active operation, removes any newly staged asset and retains finished projects. The first successful project opens after the queue settles, carrying partial-failure details.

Browser worker preflight estimates decoded capacity for both source and reference before reserving memory or creating a worker. WAV uses bounded chunk metadata; supported AIFF uses its byte/frame upper bound; FLAC uses a valid STREAMINFO sample count and rate; MP3 counts a bounded chain of valid fixed-rate MPEG-1/2 Layer III frames, including the Xing/Info frame and encoder padding, without trusting Xing counts. Header inspection is cancellable and reads at most 64 KiB per sparse read. Unknown or ambiguous shapes reserve the global decoded-frame maximum. The reservation estimate accounts for FLAC geometric growth, conversion and rendered artifacts, but is not a browser-process RSS guarantee. Go CDR remains the authoritative validator and returns reconstructed audio. Cancellation and failed admission release the existing browser reservation.

Native FLAC decoding no longer reserves PCM from the untrusted STREAMINFO total. It grows output only after each frame passes CRC and metadata checks, while enforcing the declared/global frame limits; a zero or unknown declared count grows under the global cap. This bounds metadata-only allocation, with geometric growth trading a bounded capacity overhead for avoiding eager allocation.

`newAudioAssetId` issues immutable source keys; IndexedDB `add`, rather than overwrite, rejects a collision. A denied write can retain canonical audio in an aggregate session cache capped at 256 MiB plus 44 bytes. A full cache rejects further imports. Session audio survives navigation within the application but is lost on reload or tab closure. Library preview uses the same WASI controller and held-scrub hook as Master. Settings duplication makes an independent audio asset and a deep settings copy.

`WorkspaceLink` keeps supported same-origin workstation routes in one document through the native History API and a pathname subscription. This avoids static-export RSC navigation reloading the page and losing session audio for newly created project IDs. Modified clicks, new tabs, downloads, hash links and external or unsupported routes retain native browser behavior. Back/Forward updates the same shell; route changes update the title, focus its heading, scroll to the top and dispose the outgoing audio graph.

Source recovery compares canonical PCM hash, sample rate and frame count. Exact relink preserves settings and album membership. Explicit replacement validates the retained chain for the new rate, clears derived artifacts and commits a complete project record with an expected source revision and asset key. New source keys are staged before metadata changes. Old source keys remain as recovery copies, capped at 64, until project deletion: localStorage autosave does not acknowledge durability. Deletion waits for unshared active and recovery assets before removing metadata; a failed partial deletion leaves the project available for retry or source recovery. Hydration validates the new optional source metadata instead of trusting stored shapes.

## Measured analysis and compatibility foundations

`internal/mastering/features.go` hashes reconstructed PCM/layout, measures normalized short Hann spectra and aggregates one-second source features every 250 ms. FFT resolution scales from 1024 to 16384 samples so high-rate low bands remain useful. Spectral windows overlap by 75% with padded endpoints and constant squared-window coverage; original-sample RMS/stereo windows remain separate. Fractional bin overlap distributes band-edge power; spectral DC removal does not alter source samples or RMS. Neutral change points use robustly scaled energy/centroid/width novelty and shorter-window refinement, with eight-second separation. This is deterministic measurement, not musical-role recognition or a learned mastering model.

`SourceIdentityContext` validates canonical stereo PCM and hashes its sample-rate/channel/frame layout and interleaved Float32 bits without FFT analysis. The canonical bypass/32-bit import response includes this identity in its existing bounded source-metrics header, so relink can compare the same identity as Deep analysis without a second upload.

`KindAnalyzeFeatures` uses the bounded worker pool through `/api/analyze/features`. Its reservation includes decoded input and 16 MiB scratch headroom. Retained summaries are charged and deep-copied for snapshots, then released on DELETE or expiry. The Deep panel reads the original stored Blob, polls the native job states and displays measured bands/neutral intervals without changing processing settings. Cancel invalidates its UI generation immediately; the pending admission is retained solely to delete the actual job once its ID arrives. POST, polling and cleanup requests have independent bounded transport timeouts. No late result may replace a newer operation or another track.

The engine now declares algorithm 1 explicitly while preserving omitted/zero legacy settings. `LatencyFrames` reports buffered audio only; `Drain` emits that buffered tail. Algorithm 1 buffers nothing, and its `Drain` returns zero without altering destinations. WASM capability exports distinguish sonic algorithm IDs from control ABI counts. The integrated application negotiates 82 controls, appending algorithm 1 and rejecting unsupported versions atomically; the legacy 81-value interface remains supported. The worklet refuses an unrecognized capability or a latency above its alignment delay. Algorithm 2 (Classic exports and live playback; opt-in for other API callers) is algorithm 1 plus a lookahead true-peak limiter. Algorithm 3 retains that limiter and adds the project-selected oversampled saturation stage. While limiting, the stage first band-limits its input with an 8th-order elliptic low-pass (`nyquistGuard`), flat to 0.45 fs (0 to +0.01 dB, unity at DC) and at least 69.99 dB down from 0.4643 fs (19.8 kHz passband at 44.1 kHz, 21.6 kHz at 48 kHz), the same passband as the export resampler. Its detector is an 8× polyphase Kaiser-windowed sinc with 48 taps per phase, accurate to 0.14% up to 0.45 fs but 10–60% low at 0.47–0.49 fs, which is why the guard exists (V1-13). It targets the ceiling minus 0.2 dB, which absorbs the 8-phase grid error (up to 0.14 dB at 0.45 fs) and gain changes inside a peak's support. Each linked-stereo gain requirement is min-held for A+47 frames, released through a one-pole curve and averaged over A frames, where A is a 1.5 ms attack. The audio is delayed by A+46 frames, so every sample in a reconstructed peak's 48-sample support is already attenuated when it is output. Every v2 setting, bypass included, passes through the same delay, so latency never depends on settings. A version change resets the lookahead. `dsp.RenderLatencyCompensated` sizes, drains and realigns the native offline renders. Below the ceiling, aligned v2 output equals v1 passed through the guard, except for float32 rounding and the dither noise sequence. `Drain` clears the guard, because a rendered file is silent after its last frame and the limiter must see that, not the guard's ring-out. Live playback matches it: the worklet marks the source's last input frame (`aurialis_live_end_input`), the engine drains the same tail into a side buffer without stopping (`Engine.DrainDetached`), and the worklet plays that tail while the pass stays finite. Repeat turned back on drops the tail (`aurialis_live_resume_input`), and the loop continues on the engine's uninterrupted output. The guard runs on the stage input whenever algorithm 2 processes, and switching the limiter or true-peak mode live crossfades guarded and unguarded audio over 5 ms (raised cosine); leaving bypass restarts the guard from silence and fades it in. Frames entering while limiting or while the guard fades out carry a protection flag through the delay line. Their computed limiter gain remains applied on exit, including after Reset modules or bypass, so previously boosted frames are not replayed at unity. After the 5 ms guard fade and lookahead drain, a neutral or bypassed chain returns the exact delayed source. A non-neutral chain with limiting disabled can then exceed full scale intentionally. A render whose settings never change is never faded. Live playback and its worklet render the project’s selected quality (algorithm 2 for Classic or algorithm 3 for Oversampled), compensating its latency; there is no separate preview render. Browser exports and live playback select that algorithm through `exportParams` and `exportScript` in `src/lib/engine-params.ts`, which copy the settings and never change the stored track or applied script. An export may request a delivery rate and dither. `mastering.ParseExportOptions` and `ExportOptions.Validate` reject an unsupported rate, an over-length output (more than `audio.MaxDecodedFrames`) or a ratio `dsp.ValidateResampleRates` refuses before any rendering. A converted export renders at the source rate without dither (`RenderDitherBits`). `mastering.ConvertExportContext` then converts with `dsp.ResampleContext` (rational polyphase Kaiser-windowed sinc, 120 dB stopband; `besselI0` is shared with the true-peak detector) and calls `dsp.FinishResampled`, which keeps only the limiter and dither: with the limiter enabled and neither `bypass` nor `abOriginal` set, it runs the algorithm 2 true-peak lookahead limiter at the delivery rate, latency-compensated, whatever `truePeak` and `algorithmVersion` say. TPDF dither follows, once. With the limiter off, levels are untouched. The delivered audio is re-measured, its gain reduction adds the delivery limiter's, and `params.ditherBits` reports the delivered dither. Unconverted exports skip all of this. The native handler and `internal/browserjobs` share this path, and their converted outputs are byte-identical.
The Export dialog's rate list (`src/lib/export-rates.ts`) duplicates two Go rules so it can disable a rate with a visible reason before a request: the 33,554,432-frame output bound (`MAX_SOURCE_FRAMES`, Go `audio.MaxDecodedFrames`) and the 4096 numerator/denominator limit with the 8–192 kHz source range in Go `resampleRatio` (`internal/audio/dsp/resample.go`). A change to either Go rule must change `export-rates.ts` with it; Go remains authoritative and still returns 400 `invalid_export_options`. Before a converted browser render, `browser-jobs.ts` reads the WAV `fmt ` rate through its chunk walker (AIFF and unreadable sources assume 8 kHz, the worst case), adds three decoded-size copies per unit of rate ratio to the memory estimate, and scales the worker deadline by 1 + 1.5 × max(1, ratio).

Advanced reuses a shared EQ-band control group for enable/type/frequency/gain/Q and a shared limiter-release control. High-pass retains gain for other filter types but offers no gain adjustment in sliders, pointer movement or Up/Down keys. All curve markers remain visible; only the selected band owns a 44 px drag target, avoiding overlapping touch targets. Band buttons and labeled fields provide equivalent selection and adjustment.

## Source-bound ScriptV2 schedule foundation

`internal/mastering/script_v2.go` validates a strict, bounded typed contract before any render. Native rendering verifies its identity against actual reconstructed PCM. The measured proposal generator uses neutral sections and regularized EQ fitting against a smooth spectral trend; findings state the heuristic limits. Generated baselines retain algorithm 1, sample-peak limiting and disabled repair. Schema version 2 does not activate a second sonic algorithm. `internal/mastering/starting_points.go` holds the five conservative `ProposalBaseline` recipes (Optical or VCA compression with auto release off, −1 dBTP ceiling, one signature EQ move of 1–1.5 dB per profile, ratio ≤ 2, drive ≤ 8%, width ≤ 104%; [recipes](mastering-controls-research.md#deep-proposal-baselines)), the MUB-5 section-move caps, the threshold search and the Level match. `calibrateCompressorThreshold` renders input gain, EQ and the compressor only and searches (bracketed Illinois false-position search, usually 4–8 renders) for the threshold that gives the profile's average reduction, measured by `dsp.Engine.GainReductionStats` over frames whose detector reads above −60 dBFS. The finished script is rendered through algorithm 2 (`exportScriptV2`, the transform the browser's `exportScript` must match; a shared golden in `internal/mastering/testdata` checks both). The loudness shortfall becomes one compressor-makeup Level match (`searchLevelMatch`): at most three more export renders with a secant step, bounded so a positive gain never pushes the export limiter's predicted peak reduction past 2 dB (half the heavy-limiting finding) and never above +12 dB, until the prediction is within 0.1 LU of the source. The returned prediction is the export render of the chosen gain, and its metrics and gain-reduction statistics drive the loudness, crest and heavy-limiting findings. Legacy `ProfilePreset` (version 1 jobs and `profile` renders, deprecated) keeps its character with a −1 dBTP ceiling; `profile` renders use algorithm 2 and the true-peak limiter. `dsp.ValidateParams` rejects any ceiling above −1 dBTP on every route.

`internal/audio/automation` compiles up to 128 moves with 256 points each into fixed-capacity target indexes. It resolves baseline-relative values once, coalesces collinear points and rejects overlapping or out-of-range envelopes. `internal/audio/automator` shares the evaluator between native and WASI processing. Input gain and width are evaluated per sample at their original DSP stages; other controls use an absolute device lattice no longer than 1 ms with explicit parameter-error bounds, including fades. Bypass and module enable states remain authoritative. A rational source/device clock retains fractional phase across compatible revisions and loop wraps; seek reconstructs envelopes from source zero and resets DSP history. No universal click-free or hard deadline guarantee follows.

The separate numeric schedule ABI stages one bounded move per call into an inactive preallocated slot, then atomically publishes baseline and revision. It binds source identity supplied by the host and rejects static edits or binding a different source while attached. Binding the same identity is idempotent. Detach restores the explicit baseline. HTTP compilation reports `sourceVerified: false` because it receives a script, not PCM; browser integration must compare authoritative source metadata, while native render hashes its actual input. The integrated browser controller and Deep editor attach these schedules through explicit staged/commit/acknowledgment messages. Compiled-WASI parity and Node timing probes remain kernel evidence; the bounded captured-input browser proof is described below.

`NewSourceClock` tracks a bound source independently of whether automation is attached. Hosts bind before the source epoch, align an explicit seek when needed and process only actual device-source frames; hold/pause must not submit processing frames. Static and bypassed blocks advance the rational clock, so first Apply inherits exact phase and existing DSP history. Same-identity binding changes neither phase nor history. Changing identity while detached starts a new phase-zero clock without resetting DSP history; hosts explicitly seek/reset the new playback epoch. Seek is available while detached or attached and resets DSP history. Reset seeks to zero while retaining identity, loop policy, attached schedule and accepted revision. Detach/reapply preserves phase, including fractional loop overshoot. No wall-clock playback position is inferred.

Bounded local acceptance combines native/API/compiled-WASI fixtures with a fresh 70-case existing-UI browser pass after the transport focus correction. The captured-device-input oracle preserves static-prefix DSP history and source phase. That foundation fixture is test infrastructure rather than actual browser automation evidence; the later integrated browser fixtures below exercise the real AudioWorklet. ## Integrated Deep editor and live publication

`DeepProposalPanel`, `DeepTimeline` and `DeepMoveEditor` reuse shared controls and a mobile bottom sheet/desktop inspector. The **Deep engineer profile** select is the only profile control; the legacy static profile cards were removed (V1-09). The panel lists every static field Apply changes from the current settings (`proposal-changes.ts`) and the predicted export loudness, true peak and crest stored with the draft revision they measured; an edited draft says the prediction no longer applies. Sections, warnings and move descriptions state their heuristic limits. A horizontally scrollable five-lane timeline has labeled move/form alternatives; AI Repair is explicitly unavailable. Draft changes only update `deepMastering.proposal`, never the applied audio snapshot. Reanalysis of any existing draft requires explicit replacement confirmation with complete track/proposal/profile ownership checks; Keep/Escape performs no POST. Shared dialogs portal to the document body so sticky A/B and transport controls cannot receive pointer input through the overlay. Mute/solo become audible only through explicit Apply; solo filters the submitted copy without changing the authored draft.

`useDeepPlayback` snapshots source revision/key, requested baseline and prior applied revision. Preparation verifies the canonical Blob, calls the Go compiler and constructs fixed numeric arrays. The worklet stages one bounded move per quantum, requests host commit authorization and acknowledges complete publication. The store then compare-and-swaps `applied`; pending static edits leave the old acknowledged playback/export snapshot selected until a complete revision is accepted. Postcommit uncertainty fails closed by stopping and rebuilding the graph. Detach and Revert have the same stale-source/settings checks; Revert restores the full first-Apply settings snapshot and Detach restores the applied static baseline. Both retain the draft.

The controller first binds actual verified source metadata, waits for source-arm acknowledgment and publishes a shared future device epoch aligned to 128 frames. The existing AudioBufferSource performs any source/context rate conversion (none up to 48 kHz, where the context runs at the source rate); TypeScript does not implement sample-rate conversion or envelope evaluation. Go advances its independent rational clock through static playback, attached processing and fractional loop wraps. Seek resets source epoch/history; pause stops submission. Master export and release diagnostics post the acknowledged script for native source verification; Library preview attaches the same accepted schedule. Static target-loudness and album normalization are blocked until Detach.

Finite playback fixes the native source and Go loop policy for the complete epoch. A 24-byte shared buffer guarded by an odd/even sequence publishes generation plus safe-integer device start/end frames; finite end frames include exact rational duration and the block-rounded alignment delay. Non-looping native conversion uses zero exterior rather than borrowing periodic samples. The worklet drains all valid delayed samples, then silences at the integer output deadline. Enabling Repeat mid-finite pass preserves that pass and prepares a clean epoch afterward; the honest Preparing status allows a gap. Disabling it in a periodic epoch preserves periodic conversion/history through the next input cycle and publishes only an audible stop; a later enable removes the stop. The latest intent wins during delayed arm. This is output-ring drainage, not extra IIR-decay synthesis. A future kernel with lookahead needs a separate finite EOF/drain contract; these algorithm-1 ring tests do not validate that behavior.

`serve-e2e.sh` builds an isolated temporary QA binary that embeds one static audio-thread speaker tap. The normal Go handlers, CSP, DSP modules and production binary remain unchanged. The script refuses to overwrite a staged observer, removes the staged asset after embedding and traps cleanup of temporary binary/server/assets on exit or build failure. The production smoke test requires the observer URL to return 404. The bounded SAB tap observes the actual destination feed with timestamps; it is distinct from the raw wet-ring observer and from a delayed main-thread ScriptProcessor callback.

Strict hydration rejects malformed/source-stale Deep records while preserving legacy mastering settings and reporting recovery guidance. Exact source relink advances the record’s source revision; replacement removes derived Deep state. A localStorage failure retains the prior durable JSON, reports session-only changes and offers validated draft/applied JSON downloads without silently truncating points. Aurialis’s accelerating 2×/4×/8× hold speeds, one-second/Alt 0.1-second keyboard steps and ten-second no-next-track fallback are product choices responding to the user’s workflow, not universal platform standards.

Supported Media Session actions own only the current mounted player and are removed on disposal. Media keys provide play/pause/stop/seek/restart/next where supported. Shared mastering sliders, monitor volume and EQ nodes expose double-click/Backspace reset to canonical defaults, clamped to the source-rate range.

### Added DSP algorithms and limits

The processing order is input/legacy repair → EQ → optional De-Harsh → optional multiband → broadband compressor → saturation → stereo → sample limiter/output/dither. The user-facing repair workflow remains unavailable; De-Harsh is a separate stage.

- Compressor topologies (`internal/audio/dsp/compressor_models.go`) each supply a detector, transfer curve and program-dependent release; all four share the attack/release gain smoother, so a topology change glides and starts the new detector fresh. Optical senses peaks over 5 ms and adds a second, exposure-dependent release stage (0.5–3.5 s): a 50 ms burst recovers 90% in about 115 ms, three seconds of heavy work in about 1.2 s. Variable-mu averages the rectified signal over 2 ms and grows its ratio from 1:1 at threshold − knee towards the set ratio. FET senses peaks over 0.5 ms. VCA senses linked RMS over 5 ms. Averaging detectors are sine-calibrated (+3.92 dB rectified, +3.01 dB RMS), so a steady 1 kHz tone lands within 0.15 dB of the static curve on every topology. Auto release depends on topology: Optical fixes its fast stage at 60 ms and relies on the slow stage; Variable-mu (80–1000 ms) and FET (40–250 ms) lengthen with recent applied reduction; VCA moves from 600 ms on dense material to 60 ms on sparse peaks by crest factor. Auto release ignores the stored manual release. These are behavioral models with original constants, not circuit or named-hardware emulations. Until 2026-10-25 every topology was a label over one peak detector.
- Mid and Side gains scale the encoded center/difference signals separately, alongside width and optional bass narrowing. The existing bass-narrowing filter remains its own implementation, not a validated Linkwitz–Riley specification.
- De-Harsh uses a stereo-linked band detector at the selected frequency, threshold-triggered attenuation and a requested maximum reduction. The detector is normalized by its Q after adversarial tests exposed excess attenuation. Transition and range results remain bounded by the tested signals; see the current checkpoint in tasks.
- Multiband splits three bands with fourth-order Linkwitz–Riley crossovers (two cascaded Butterworth SVF stages, −6.02 dB per branch at each crossover, 24 dB/oct). The low band also passes through the upper crossover's all-pass, so idle bands sum to a flat-magnitude all-pass: magnitude is unchanged within 0.01 dB, phase rotates and a sample null against the dry signal is not expected. Independent linked-stereo gain reduction and makeup alter that sum. This is minimum-phase, not linear-phase. Until 2026-10-25 the split was first-order complementary (sample-exact when idle, but a low-band cut leaked to −1 dB two octaves above its crossover).
- Tube, Tape and Transformer are original bounded coloration models. Tube uses a biased nonlinear curve; Tape adds frequency-dependent softening; Transformer shapes a low-frequency path while retaining the remaining signal. Two interpolated sub-steps and antiderivative processing reduce some nonlinear artifacts but the averaging decimator is not a brick-wall filter. No alias-free, named-hardware or Waves-equivalent result is claimed. A coherent 32768-frame, 7001-bin tone at −6 dBFS measured a selected alias component near −71.4 dBFS for Tube/Tape at 10% drive and approximately −48.4/−49.4 dBFS at 50% drive, at both 44.1 and 48 kHz after warm-up. This one-tone result is not a broadband or all-drive alias specification. Saturation parameter updates rebase antiderivative history to the changed curve after adversarial tests exposed a drive-change spike; that repair does not imply every parameter is continuously interpolated. Clean leaves the saturation stage unchanged; legacy Warm/Thick/Crisp remain for existing sessions. Since 2026-10-25 every character keeps unity fundamental gain for −12 dBFS peaks (program level) and a flat low-level response to 20 kHz: the wet path adds the ADAA harmonic residual to the time-aligned input instead of using ADAA's half-step-delayed linear response, which had dulled 16–20 kHz by 2–9 dB. Crisp keeps a small presence tilt and Tape a small broadband cut by design. The linear correction lets steep high-frequency edges through at their unsaturated slope, so softening is frequency-dependent rather than a hard peak bound. Saturation arithmetic uses explicit conversions so native and WebAssembly output stay bit-identical. Quiet signals gain at most about 2.6 dB (Crisp 5.3 dB with its tilt) at 100% drive, and a 0 dBFS sine softens by about 7.4 dB; Warm's even-order term can raise asymmetric peaks by about 1 dB. Punchy Commercial and Bass Heavy presets raise compressor makeup to 7.5 dB to keep the loudness that the former Thick/Crisp gain supplied, and Dynamic & Open input drops 2 dB to stay the quieter profile.

New controls enter the same Go core in native export and live/offline WASM. This source sharing is not sufficient evidence of live continuity, numerical parity or safe parameter transitions; the expanded fixtures and actual-browser gates are tracked below in [tasks](tasks.md).

## DSP and measurement boundaries

The Go engine implements gain, five EQ bands, optional De-Harsh and three-band dynamics, compressor, saturation, stereo processing and limiting. Compressor topologies have distinct behavioral models (above); the saturation characters are heuristic models. Mono-bass uses side-channel filtering that preserves the mono mid signal; it is not a validated textbook Linkwitz–Riley crossover. Current mathematical and safety tests establish particular transfer behaviors; they do not certify named hardware emulations, a Waves-equivalent chain, formal ITU/EBU conformance, or anti-aliasing performance. Limiter safety remains a sample-domain boundary; its streaming cubic interpolation is separate from the offline peak meter.

Live metrics are block-window sample peak dBFS, RMS, crest and correlation of the audible output, not whole-track LUFS or true peak. Controller silence readings use a finite −120 dBFS floor; the UI displays that as −∞ with no invented crest reading. Silence correlation is a defined convention, not evidence of stereo coherence. The API meter uses independent BS.1770/DeMan K-weighting, 400 ms windows at 75% overlap, an absolute −70 LUFS gate followed by a relative −10 LU gate, and a trailing three-second short-term interval. Shorter clips use their available duration for diagnostic reporting. There are two true-peak meters (V1-13). The export meter (`MeasureStereo`: export reports, Release Check, `measureAudio`) has no real-time budget, so it reconstructs each 49,152-frame block with 8,192 frames of context on each side by spectral shift on a 4× grid, plus a parabola through the largest grid value and its neighbors; it reads ≤ 0.1 dB on all content except sustained coherent energy within about fs/16384 of Nyquist, which is unphysical in real audio and removed by the guard in limited exports. That exception follows from the physics: a full-scale Nyquist alternation that flips polarity peaks at the flip like (2/π)·ln N, so no finite context reads it (QA measured 2.94 dB low on a 60 s flip at 44.1 kHz; the regression test pins the bound). It does read files that start or end on a crest, and unlimited exports dense up to 0.5 fs, within 0.04 dB. The live display meter (`LoudnessMeter`) is a 4× Kaiser-windowed sinc with 48 taps per phase (β 7, accurate to 0.05% at 0.45 fs) with the same parabola, which cuts a sine's grid error from 0.69 dB at Nyquist to 0.07 dB; it lags 23 samples and reads within 0.07 dB on limited exports (QA worst 0.066 dB low). On unlimited content above 0.46 fs it can read far lower (9.6 dB on the Nyquist flip, 0.57 dB on a 19.9 kHz tone with abrupt edges at 44.1 kHz), and abrupt edges count as near-Nyquist content; the live tile is an estimate, and the export check is authoritative. Both replaced the 49-tap 4× Hann filter of BS.1770-4 Annex 2, which read near-Nyquist peaks up to 1.7 dB low. Fifteen external FFmpeg comparisons at 44.1/48/96 kHz (`pnpm run test:meters`) report at most 0.0542 LU loudness error and 0.0051 dB peak error (0.0312 dB with the old filter) for the selected fixtures; abrupt 8 kHz boundaries can differ by 0.58 dB. These are bounded fixture comparisons, not all-waveform guarantees or formal standards certification; the algorithm-1 limiter has no true-peak/lookahead guarantee. Algorithm 2 is checked against a long-sinc reference (`internal/audio/truepeakref`, test-only): the whole zero-extended signal reconstructed by spectral shift on a 32× grid, exact on sines to 0.498 fs and within 0.01 dB of a direct ±1024-tap Kaiser sinc. On the dense mix with every module on (60% Crisp or Tube, or 0.6% Warm), a hot 10 ms limiter, and a torture mix of gated 20 kHz–0.498 fs tones, noise in the top 2% of the band and a hard-clipped tone, at 44.1/48/96 kHz and −1/−1.5/−2 dBTP ceilings, plus converted 16-bit exports, every limited export measures at least 0.13 dB under its ceiling (QA: 360 adversarial renders, worst 0.136 dB under) and the export meter reads within 0.01 dB of the reference, the live meter within 0.07 dB (`wasm/dsp/true_peak_ceiling_test.go`). Before V1-13 the same exports reached 1.45 dB over the ceiling while the meter read up to 1.7 dB low. An unlimited export dense between 0.47 fs and Nyquist reads within −0.037 to −0.001 dB on the export meter (`meter_truepeak_test.go`). The low-level `targetLufs` field remains metadata: Advanced rendering performs no implicit gain calibration. Simple mode explicitly measures output and adjusts an immutable input-gain snapshot toward its selected target, with bounded iterations and failure reporting when the target cannot be reached. See [`api.md`](api.md) for field limits. `pnpm run test:wasm` runs real compiled WASM/native parity fixtures; `pnpm run test:meters` runs independent FFmpeg meter comparisons. Both are wired into CI.
