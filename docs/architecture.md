# Aurialis-WASM architecture

This describes current implementation boundaries. [`AGENTS.md`](../AGENTS.md) and [`docs/tasks.md`](tasks.md) retain the full product requirements. Implementation on a branch is not verified delivery or a merge to main.

## Build and serving

`pnpm run build:binary` runs `scripts/build.sh`: compile `wasm/dsp` for `js/wasm`, copy the matching Go `wasm_exec.js`, run the Next.js static export and `scripts/sync-webui.mjs`, then compile `cmd/aurialis`. `internal/webui` embeds generated assets with `//go:embed all:embedded`. The native executable serves HTTP APIs and the frontend without Node at runtime.

`pnpm run test:binary` runs the executable from an empty directory, preventing source-tree assets from masking missing embedded files. The host serves embedded assets only; source-tree output cannot replace the embedded application. Generated assets are not committed, so a fresh `build:binary` is required for a usable application. Dynamic route IDs resolve to static exported shells and browser state supplies the project.

The default bind address is `127.0.0.1:8080`. The middleware emits COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, CSP, nosniff and frame denial headers. Host/Origin and Fetch Metadata checks protect localhost; these checks are not a remote multi-user authentication system.

## Browser audio paths

The current live-playback follow-up separates listening from offline export. Integration and fresh UI/output-capture verification are pending; older completed-buffer preview evidence in the task tracker belongs to its earlier checkpoint.

1. Home accepts PCM WAV within the existing 128 MiB plus 44-byte and 16,777,216-frame limits. Import performs bounded header preflight followed by authoritative Go content disarm and reconstruction into canonical stereo 32-bit float WAV.
2. IndexedDB stores the canonical source Blob; localStorage stores metadata/settings. Cached canonical WAV loads without another POST only after strict container/byte/frame/rate and finite-sample validation. A legacy source with another WAV layout uses the Go bypass render fallback. Missing audio blocks playback and A/B; source errors provide retry. Request failures explain the current local server, distinguish unreadable/interrupted response bodies, and preserve aborts.
3. A track mount creates a fresh `createLivePlayback` controller, AudioContext, worker and worklet graph. `public/workers/aurialis-live-worker.js` loads the matching Go runtime and compiled DSP. It processes 128-frame blocks in a bounded 256-slot SharedArrayBuffer bridge. `public/worklets/aurialis-live-worklet.js` never runs Go, performs network I/O or waits for the worker; a stalled bridge reports an error instead of silently substituting the original.
4. Dry and processed blocks share an approximately 80 ms alignment delay (rounded to whole blocks). **A Processed** is the default; **B Original** uses the same clock and aligned source, with an 8 ms crossfade. Volume is a monitor control; automatic A/B gain matching and the Match level option are removed. Versioned parameter updates identify when new settings reach audible output. Pause, seek and disposal reset bounded stream state; generation resets are idempotent so delayed control messages cannot erase an active generation twice.
5. The worklet computes sample peak, stereo RMS, crest and correlation from actual mixed/monitored output over roughly 50 ms windows. The controller reads a 4096-point FFT for each audible channel and averages their linear power before converting to dB, up to 20 times per second. The warm `LiveSpectrumChart` is the primary measured visualization; the compact Advanced EQ response/editor remains a separate settings view with round 44 px touch targets and keyboard/form alternatives. The waveform uses clay to indicate the played portion.
6. Native export posts canonical source and the selected settings to the same pure-Go DSP API, preserving original sample rate and frame count. A device AudioContext can resample a different-rate source before live DSP, so cross-rate live/native sample identity is not claimed. Same-rate signal tests must still distinguish stateful live processing, transition windows and monitor volume from a fresh offline render.

Simple genre, tone and intensity select live settings automatically. **Apply master direction** separately measures a bounded loudness normalization for export and produces a downloadable offline preview; changing that direction invalidates stale export preparation without requiring a full-song render before listening. Deep **Apply profile** updates a static live preset; it does not launch musical analysis or force a complete buffer render. Shared `processPreview` remains an offline helper, not the live audio path.

Home/source preparation, export dismissal and album rendering retain cancellation guards. Unmounting closes the previous controller, context and worker rather than reusing a disposed graph on return navigation. Worklet/worker generations and callback ownership reject stale updates. Strict source loading and graph lifetime still require integrated navigation/reopen proof at the final live checkpoint.

The original “Failed to fetch” report has no confirmed root cause. Fresh Chromium/Brave probes returned successful POST responses, while contextual error and cancellation regressions cover initial connection and response-body failures. These observations do not prove a browser permission or server failure caused the original report.

## DSP and measurement boundaries

The Go engine implements gain, five EQ bands, compressor, saturation, stereo processing and limiting. Compressor topology names currently share the same mathematics; the saturation characters are heuristic models. Mono-bass uses side-channel filtering that preserves the mono mid signal; it is not a validated textbook Linkwitz–Riley crossover. Current mathematical and safety tests establish particular transfer behaviors; they do not certify named hardware emulations, a Waves-equivalent chain, formal ITU/EBU conformance, or anti-aliasing performance. Limiter safety remains a sample-domain boundary; its streaming cubic interpolation is separate from the offline peak meter.

Live metrics are block-window sample peak dBFS, RMS, crest and correlation of the audible output, not whole-track LUFS or true peak. Controller silence readings use a finite −120 dBFS floor; the UI displays that as −∞ with no invented crest reading. Silence correlation is a defined convention, not evidence of stereo coherence. The API meter uses independent BS.1770/DeMan K-weighting, 400 ms windows at 75% overlap, an absolute −70 LUFS gate followed by a relative −10 LU gate, and a trailing three-second short-term interval. Shorter clips use their available duration for diagnostic reporting. The offline peak estimate uses a 49-tap, 4× Hann-windowed sinc interpolator with end padding. Fifteen external FFmpeg comparisons at 44.1/48/96 kHz reported at most 0.0542 LU loudness error and 0.0312 dB peak error for the selected fixtures; abrupt 8 kHz boundaries can differ by 0.58 dB. These are bounded fixture comparisons, not all-waveform guarantees or formal standards certification; the limiter has no validated true-peak/lookahead guarantee. The low-level `targetLufs` field remains metadata: Advanced rendering performs no implicit gain calibration. Simple mode explicitly measures output and adjusts an immutable input-gain snapshot toward its selected target, with bounded iterations and failure reporting when the target cannot be reached. See [`api.md`](api.md) for field limits. `pnpm run test:wasm` runs real compiled WASM/native parity fixtures; `pnpm run test:meters` runs independent FFmpeg meter comparisons. Both are wired into CI.

## Jobs, uploads and lifetime

`internal/server` handles bounded multipart requests and decodes audio in memory. User-supplied filenames do not become disk paths. Decoders accept mono/stereo PCM/float WAV and 16-bit PCM AIFF, rejecting multichannel input. AIFC and compressed formats are rejected; recognized compressed signatures are not evidence of decoders. Reconstruction emits new WAV samples and discards metadata. Signature checks inspect headers/metadata/trailers, never arbitrary PCM bytes; this is not steganography detection. Finite float-WAV headroom survives decode/export, while non-finite values are sanitized and integer exports clamp to full scale.

`internal/jobs` owns the experimental Deep-analysis and heuristic separation queues and cancellation. These APIs are not connected to enabled product workflows. Multipart bodies have a hard 129 MiB cap, audio files a 128 MiB plus canonical-header cap, and decoding a 16,777,216-frame cap. One expensive POST is admitted at a time; another receives retryable 503 before body allocation. Job decoded input, float output, encoded artifacts and scratch reservations are bounded at 256 MiB, retention at 64 records, and worker count at four. These are finite working/admission budgets, not a total RSS guarantee. Isolated 3/5-minute native render and canonical re-upload measurements are recorded in the task tracker; full browser/album-scale and arbitrary concurrency behavior require separate evidence. Jobs time out after two minutes; terminal artifacts expire after 15 minutes. See [`api.md`](api.md).

## UI and remaining product scope

Next.js 16 App Router, React 19, strict TypeScript and Tailwind v4 provide the warm editorial design. Production icons are custom inline SVGs. Shared controls and the shell support mobile and desktop layouts; automated axe and overflow checks are evidence for tested routes and interactions, not blanket WCAG certification.

The production store starts empty and discards legacy example projects, simulated scripts/stems and stale release scores. Simple listening updates live tone without hidden target gain; explicit Apply measures export settings. Profile mastering applies one of five static live presets; musical analysis, automation and AI repair remain open. Smart Split exposes an unavailable state without fabricated artifacts. Albums measure and render tracks sequentially toward −14 LUFS, producing individual 24-bit PCM WAV downloads in a 128 MiB session cache while retaining original sources. Cache keys include the track IDs, order and processing settings; settings/sequence changes or leaving the page invalidate those artifacts. Sequence controls are locked while rendering. There is no ZIP or persistent mastered-artifact store. Reference direction explicitly blends project EQ settings; both curves use one logarithmic frequency/gain scale while respecting each track’s sample-rate bandwidth. Saved metrics identify whether they describe source audio or an album render. Spectral matching remains open. Release diagnostics measure native rendered output against working targets and invalidate results on track/settings changes; they do not certify platform delivery.

Shared Tailwind button variants, dialog surfaces, control groups and module disclosures provide ordinary layout and interaction styling. The shared `DSPModule` uses native disclosures for keyboard and touch access; five-band EQ has direct pointer/keyboard interaction and labeled form alternatives. Global CSS retains design tokens, base rules and specialized audio/artwork styling. Inline SVGs remain the only production icon source. See [tasks](tasks.md) for final-checkpoint verification and outstanding scope.
