## Measured source features

`POST /api/analyze/features` (alias `/analyze/features`) accepts one multipart `file` through the existing reconstruction and admission path. Options and query parameters are rejected. It returns the existing **202** job envelope with `kind: "analyze_features"`. Health advertises `featureAnalysisMethod` and `featureAnalysisVersion`. Poll `GET /api/jobs/{jobId}?wait=1`; the native status values are `queued`, `running`, `done`, `failed` and `cancelled`. A `done` response includes `features`, not a mastering script. `DELETE /api/jobs/{jobId}` cancels and releases retained summaries. Failed delivery of the admission response cancels that job.

`features.version` is `"1.0"`. Its `source` contains `pcmHash`, `sampleRate` and `frames`. SHA-256 covers little-endian uint32 sample rate, uint32 channel count 2, uint64 frame count, then interleaved little-endian L/R Float32 bits. This binds measurements to reconstructed stereo PCM and layout.

The five bands are 20–120, 120–500, 500–2000, 2000–6000 and 6000–20000 Hz. Each reports `lowHz`, `highHz`, `usableHighHz`, `bandwidthHz`, `powerDb`, `densityDbPerHz` and `valid`; unavailable bandwidth is explicit. Power is stereo-averaged mean square; unequal band widths are not interchangeable tonal targets. DC is excluded from spectral diagnostics while original RMS/stereo energy retains it. Normalized Hann FFT frames (1024–16384 samples, chosen by rate) use 75% overlap and padded endpoints with constant squared-window coverage, then aggregate into one-second windows at quarter-second hops. Raw RMS/stereo windows use original samples independently of spectral weighting. Very short sources use their available duration.

`frames` contains `centerFrame`, `rmsDb`, `centroidHz`, `sideMidDb` and `crestDb`. `windowCrestPercentiles` holds p10/p50/p90. `sibilanceRatioDb` is 6–12 kHz power relative to usable power at or above 20 Hz; it is neither a sibilance diagnosis nor a crest factor. Finite floors/conventions and bandwidth warnings accompany low-information signals.

`sections` partition the exact source-frame interval with neutral `Section N` names, `roleHint: "unknown"` and `confidence`. Confidence is a bounded novelty-strength heuristic, not a calibrated musical-role probability. Boundaries require eight-second spacing on sufficiently long sources; silence, constant fixtures and short clips can have one section. No EQ proposal, processing move, Verse/Chorus classification or trained-model claim is returned.

The job reserves decoded input plus 16 MiB analysis headroom; retained feature arrays are charged conservatively until cancellation/expiration. GET snapshots deep-copy mutable feature slices. Existing 256 MiB/64-job limits, worker timeout, retention, Host/Origin and upload bounds apply. Browser source analysis releases its admitted job after copying successful diagnostics, and deletes a known admitted job after Cancel. Cancel detaches the UI immediately even when the admission response is held; bounded transport failure falls back to server timeout/retention.

## DSP compatibility and capability foundation

The optional `params.algorithmVersion` accepts omitted/zero/one as unchanged algorithm 1; null, fractional, negative and unimplemented values are rejected. The sonic algorithm is independent of the numeric control ABI. Existing 81-value controls remain supported and production still publishes its 664-byte shared packet. Negotiated ABI 2 appends explicit algorithm ID 1 as value 82, through a separate buffer/setter; it does not enable algorithm 2 or migrate the shared packet.

Both WASM modules export `aurialis_control_count(abi)` (81 for 1, 82 for 2, zero otherwise), `aurialis_algorithm_supported(version)` (one only for explicit algorithm 1), `aurialis_latency_frames()` and `aurialis_live_drain()`. The appended interface uses `aurialis_control_buffer_v2` and `aurialis_set_controls_v2(count)`; invalid length/version rejects atomically. The worklet requires implemented algorithm 1, matching current count and zero buffered latency before playing. Native `LatencyFrames()` and `Drain()` currently return zero; drain preserves destination contents and does not synthesize an IIR-decay extension. Transport alignment and filter phase are separate from buffered DSP latency.

## Security and resource contract

The executable binds only to loopback IPs (default `127.0.0.1:8080`). `AURIALIS_ADDR` takes precedence over `PORT`, then `-addr`; a numeric `PORT` becomes `127.0.0.1:<port>`. The request Host must match an allowed local authority and the actual port. A supplied Origin must be HTTP with the same authority; `null` is rejected. Fetch Metadata permits only `none` or `same-origin` when supplied. Rejections return 403 JSON. These checks do not provide remote authentication.

Responses carry COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, and a CSP restricted to same-origin assets with hashes for the embedded bootstrap scripts. WASM uses `application/wasm`. Browser fonts are self-hosted. Permissions-Policy disables unused device access; WAV download responses also carry a sandbox CSP.

Multipart bodies are capped at **129 MiB including overhead**. The audio file is capped at **134,217,772 bytes** (a maximum stereo-float WAV including its 44-byte header); the browser uses the same file-byte cap, allowing 128 MiB of stereo-float samples plus the canonical header. `-max-upload-bytes` / `MAX_UPLOAD_BYTES_OVERRIDE` can lower the request cap, never increase it. Decoding permits **16,777,216 frames**: about 349.5 seconds at 48 kHz or 174.8 seconds at 96 kHz; byte limits can shorten this. Canonical float re-upload fits the multipart limit.

One expensive POST upload/render is admitted at a time. Another receives **503 busy**, with `Retry-After: 1`, before its body is read. Worker jobs reserve decoded input, float output, encoded artifacts and scratch headroom within **256 MiB**, retain at most **64 jobs**, and return **503 queue_full** when admission fails. Automatic workers use at most two CPUs; explicit workers cannot exceed four. The reservation is a job working budget, not a process RSS guarantee. A separate single-request frame/body bound limits synchronous scratch. Representative native 3/5-minute tests and observed memory belong in the task tracker; browser and arbitrary workload memory are not certified by those probes. Worker timeout is two minutes; terminal artifacts expire after 15 minutes, checked every minute.

Uploaded names are validated and never used for host disk writes. Parsing/decoding stays in bounded memory. Only mono/stereo input is supported; multichannel input is rejected. Supported inputs are WAV PCM 8/16/24/32-bit integer or 32-bit float, and 16-bit PCM AIFF. AIFC and compressed MP3/FLAC/OGG/M4A/AAC decoding are unsupported. WAV checks include declared RIFF length, alignment, byte rate, chunk bounds, duplicate chunks and whole frames. Reconstruction creates new samples without metadata. Executable/archive/script signatures are inspected in headers, metadata and outside-container trailers, not arbitrary PCM bytes. Legitimate sample bytes can match those signatures. Reconstruction is the audio-only boundary; this is not PCM steganography detection or a universal malicious-content guarantee.

Errors use JSON with `error`, `detail` and numeric `status`. Malformed fields/container/params return 400, oversized requests 413, rejected authority/origin 403, missing resources 404, admission failures 503, and encoding failures 500.

## Routes

Both root and `/api` aliases exist for health, render, analysis, separation and job routes.

| Method and route | Behavior |
|---|---|
| `GET /health` | 200 readiness JSON, actual embedded WASM availability, profile names and explicitly heuristic model/analysis identity. This is not a browser WASM execution test. |
| `POST /master/render` | Synchronous native DSP render from actual uploaded audio; 200 WAV or JSON. |
| `POST /analyze/features` | 202 source-bound spectral/neutral-change-point diagnostic job; used by Deep measured-source analysis. |
| `POST /analyze/deep` | 202 experimental deterministic energy/section analysis job. No trained AI/LLM inference; disabled in the product UI. |
| `POST /separate` | 202 deterministic frequency-based decomposition job for 2–6 outputs. No trained instrument separation; disabled in the product UI. |
| `GET /jobs/{id}` | 200 job snapshot; `/status` and `/result` aliases return the same snapshot. `?wait=1` waits up to four seconds while queued/running. |
| `DELETE /jobs/{id}` | Cancels queued/running work and clears terminal artifacts too; repeated cancellation of a retained record is idempotent. Missing or expired ID returns 404. |
| `GET /jobs/{id}/stems/{stemName}` | 200 WAV when an artifact exists; optional `.wav` suffix; 404 otherwise. Traversal components are rejected. |

`GET /health` reports `status: "ok"`, `service: "aurialis-wasm"`, `version: "0.1.0"`, `wasmDsp: true`, `wasmDspReady` based on embedded module presence, `gpu: false`, `models: ["deterministic-frequency-split"]`, `separationMethod: "deterministic-frequency-split"`, `analysisMethod: "deterministic-energy-heuristics"`, `featureAnalysisMethod: "normalized-hann-spectrum-and-novelty"`, `featureAnalysisVersion: "1.0"`, numeric `maxUploadBytes`, `maxAudioFileBytes`, `maxDecodedFrames`, `maxConcurrentAudioRequests`, `jobMemoryBudgetBytes`, and `profiles`. The readiness field does not load or execute WASM.

### Rendering

Send `multipart/form-data` with required `file` and optional fields:

- `profile`: `Warm Analog`, `Punchy Commercial`, `Dynamic & Open`, `Vocal Forward`, `Bass Heavy`; compatibility aliases include `indie_warmth`, `modern_pop_polish`, `pop_punk_air`, `hip_hop_low_end`, `metal_wall`.
- `params`: JSON overlay on default/profile DSP parameters. Unknown fields, nulls, trailing JSON, invalid enums, non-finite/out-of-range values and non-five-element `bands` arrays return 400. EQ band types include `low_shelf`, `peaking`, `high_shelf`, and actual `high_pass` processing. Parameters include `bypass`, `abOriginal`, `loudnessMatchAb`, `inputGainDb`, `eqEnabled`, `bands`, `compressor`, `saturation`, `stereo`, `limiter`, `repair`, `deHarsh`, `multiband`, `ditherBits`. Field presence does not guarantee every advertised analog topology has distinct behavior.
- `bitDepth`: `16`, `24` (default), or `32`; other values return 400. 16/24-bit PCM receives TPDF dither and clamps to integer full scale; 32-bit float decode/export preserves finite headroom above ±1. NaN and infinity are sanitized to zero. Processing can change source levels; bypassed float round-trips preserve headroom.
- `format=json`, or `Accept: application/json`: return `status`, `sampleRate`, `frames`, `duration`, `bitDepth`, `params`, `beforeMetrics`, `afterMetrics` instead of audio.

Supplied `bands` arrays require exactly five complete EQ objects; supplied `multiband.bands` arrays require exactly three complete dynamics objects. Case variants such as `Bands`, `Multiband` and nested `BANDS` receive the same array validation. Every differently cased alias supplied in one object must satisfy those count and completeness checks. Numeric ranges are validated on the final decoded settings after alias resolution. Identical duplicate JSON keys retain the decoder's existing last-value behavior. Rejected settings return 400 without applying the update.

WAV output uses `Content-Type: audio/wav`, `Content-Disposition: attachment; filename="aurialis-mastered.wav"` and compatibility headers `X-Aurialis-Before-LUFS`, `X-Aurialis-After-LUFS`, `X-Aurialis-After-Peak-dBTP`. Rendering preserves the uploaded sample rate and frame count. Metric fields are `integratedLufs`, `shortTermLufs`, `truePeakDbtp`, `samplePeakDbfs`, `dynamicRangeDb`, `correlation`, `lowBassCorrelation`, `dcLeftDbfs`, `dcRightDbfs`, `clippingSamples`, `gainReductionDb`; see the measurement limitations below.

For an audio response with `params.bypass=true` and `bitDepth=32`, the server additionally sends `X-Aurialis-Source-Metrics`: at most 4096 bytes of JSON containing `sampleRate`, `frames`, `duration`, `beforeMetrics` and `afterMetrics`. Both metric objects describe the reconstructed source and use the schema above. The server measures this bypass source once and reuses its decoded samples instead of running the enabled-DSP render path. WAV responses declare their exact `Content-Length`. This changes neither CDR validation nor request, frame, admission or timeout limits.

The browser import uses this single response instead of separate measurement and reconstruction POSTs. It rejects missing, oversized or invalid measurement headers, cancels an unusable response body, checks canonical byte size (`44 + frames × 8`), then validates the decoded sample rate and frame count against the header. These checks describe transfer consistency; they do not replace the authoritative native decoder.

```bash
curl --fail-with-body http://127.0.0.1:8080/api/master/render \
  -F file=@source.wav -F 'params={"inputGainDb":-6}' \
  -F bitDepth=24 -o mastered.wav

curl --fail-with-body http://127.0.0.1:8080/api/master/render \
  -F file=@source.wav -F 'params={"bypass":true}' -F format=json
```

### Expanded mastering parameters

These fields extend the existing `params` JSON object; no route or upload contract changes. Omitted fields preserve default/profile values. New effects default off. Disabled modules still require valid parameters. The all-zero omitted legacy `deHarsh` and `multiband` structs remain accepted for compatibility.

| Object | Fields and accepted API ranges |
| --- | --- |
| `compressor` | `kneeDb`: 0–24 dB; `makeupDb`: −24–36 dB; `sidechainHpfHz`: 0–1000 Hz (0 disables detector filtering); `autoRelease`: boolean. Existing threshold/ratio/attack/release fields remain. |
| `stereo` | `crossoverHz`: 20–1000 Hz, used when `monoBass` is true; `midGainDb`, `sideGainDb`: −24–24 dB. Existing enable and width controls remain. |
| `saturation` | `character`: `Clean`, `Tube`, `Tape`, `Transformer`, or legacy `Warm`, `Thick`, `Crisp`; `amount`: 0–100. Clean is identity and retains, but ignores, amount. |
| `deHarsh` | `enabled`: boolean; `frequencyHz`: 1000–12000 Hz; `thresholdDb`: −60–0 dB; `rangeDb`: 0–12 dB. Defaults: false, 4500, −24, 3. |
| `multiband` | `enabled`: boolean; `lowMidHz`: 40–1000 Hz; `midHighHz`: 1500–12000 Hz, greater than low/mid; `bands`: exactly three complete band objects in low/mid/high order. Defaults: false, 200, 4000. |
| Each multiband band | `thresholdDb`: −60–0 dB; `ratio`: 1–8; `attackMs`: 1–200 ms; `releaseMs`: 20–2000 ms; `makeupDb`: −12–12 dB. Defaults: −24, 1.5, 30, 150, 0. |

A supplied multiband band array must contain all five fields in each of its three objects. Unknown fields, incomplete arrays, invalid ranges and nulls fail validation rather than partially applying a chain. The frontend additionally caps frequency controls against the source sample rate. Automatic release uses its adaptive recovery instead of `releaseMs`; turning it off restores the retained manual setting. Detector HPF filters the compressor's detector rather than the audible input. These original algorithms do not establish hardware emulation, linear-phase reconstruction or Waves equivalence; implementation details and current validation limits are in [architecture](architecture.md) and [tasks](tasks.md).

This generated heuristic structure is not proof of musical section recognition, AI artifact detection or effective AI repair.

## Browser transport and request boundary

The legacy offline JS/WASM entrypoint uses intrinsic typed-array branding and metadata when checking its input and destination views. It validates all views before advancing DSP state, preserving existing shared-buffer, offset, alias-order and zero behavior. Shadowed properties on a genuine `Float32Array` cannot make its byte view exceed the actual array storage. This is a browser-library boundary correction; no ordinary GUI trigger or host-machine security compromise is established.

Live numeric settings require five EQ bands, three multiband bands when supplied, and exactly 81 finite values. Encoding completes before the shared packet enters its odd/even publication transaction. Rejected packet shapes preserve the prior payload, version and sequence; a later valid update can still be published. The current UI and hydration already preserve three multiband bands, so this correction addresses malformed runtime callers rather than a demonstrated ordinary GUI failure.

**A Processed** is the default and **B Original** selects aligned dry audio. The transport offers no Match level option or automatic loudness matching. Live playback calls the Go WASI reactor directly in AudioWorklet with a fixed numeric control buffer; it adds no new HTTP processing endpoint. The browser may resample source audio to the device context rate, while native export preserves the source rate, so cross-rate sample identity is not an API guarantee. Live settings take effect at block boundaries. The 8 ms A/B crossfade and monitor-volume ramp do not establish continuous parameter smoothing or sample-accurate musical automation.

The internal live ABI exports `aurialis_init`, `aurialis_control_buffer`, `aurialis_set_controls`, `aurialis_live_buffer`, `aurialis_live_process` and `aurialis_live_reset`, alongside memory and `_initialize`. Four 128-frame input/output views and a 81-value Float64 control vector are validated for address bounds, alignment and overlap; views refresh after memory growth. The frontend encodes the existing engine parameters into a 664-byte SharedArrayBuffer: a 16-byte header plus 81 doubles. One odd/even sequence transaction publishes values and their version together; a changing packet retains prior settings for that block without spinning.

Go validates all controls for finite values, exact booleans, enums, dither and parameter ranges before committing the chain atomically. The live sample path has no JSON parameter messages, JavaScript callback bridge or processing worker. Main-thread module fetch/compilation precedes playback; each graph initializes a fresh reactor with a positive clock and bounded entropy. The restricted host allows initialization services only and rejects host imports during control/process calls. HTTP JSON/native export and legacy browser-WASM offline preview accept the same additive DSP fields. ## Measurement limits and verification

Live playback meters are computed from actual audible blocks: sample peak dBFS, stereo RMS, crest factor and correlation. The 4096-point spectrum averages L/R power and describes the monitored processed/original selection. Measurements arrive at up to 20 Hz; animation-frame interpolation changes the drawn transition between measured traces, not the underlying measurements. These values are separate from full-track API diagnostics. Release diagnostics request native measurements of the selected rendered settings. The API meter uses BS.1770/DeMan K-weighting with 400 ms windows and 75% overlap, absolute −70 LUFS and relative −10 LU gates, and a trailing three-second short-term interval. Short clips use the available duration, which is a diagnostic approximation to standard-duration reporting. Silence reports a finite −70 LUFS floor. Offline `truePeakDbtp` uses a finite 49-tap 4× Hann-windowed sinc estimate including end padding; it is not formal certification. The streaming limiter remains sample-bounded with cubic estimation and has no validated lookahead/true-peak guarantee; the final processed sample ceiling is reapplied after level matching and dither, while original/bypass paths preserve the source. `limiter.targetLufs` is metadata only; low-level rendering does not automatically normalize to a loudness target. Simple tone changes reach the live chain without POST normalization. Explicit **Set target loudness** prepares an offline preview and requests up to eight measurement renders, estimates the compressed output response with a bracketed secant update, adjusts input gain within ±36 dB, and accepts a result within ±0.2 LU of the target only when the reconstructed peak estimate is no more than 0.2 dB above the selected ceiling. Otherwise it reports a failure. It retains the current EQ, dynamics, saturation, stereo and other settings; changing Simple/Advanced views does not normalize or replace them. Platform compliance remains unavailable. `dynamicRangeDb` is crest factor using peak and stereo-average RMS with a 1 dB floor, not EBU LRA or a standardized DR score. Correlation uses normalized cross-energy without mean subtraction; low-bass correlation filters at 110 Hz. `clippingSamples` counts frames where either channel reaches magnitude 0.9999. DC fields report the dB of the absolute channel mean. These remain diagnostic measurements. Independent comparison fixtures and limits are tracked in [architecture](architecture.md) and [tasks](tasks.md).
