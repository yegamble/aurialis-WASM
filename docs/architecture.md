## Device-local deployment boundary

The deployment decision keeps every audio byte and processing job on the user’s device. `deviceAudioRequest` maps the existing application contracts to a dedicated disposable Worker on every public origin. `internal/browserjobs` compiles the native CDR, mastering, features, Deep, Reference and numeric compiler to Go/WASM. Metadata and transferable audio buffers travel separately; PCM is never encoded as JSON or base64 in the runtime transport. The native executable remains an explicit device-local fallback through its own loopback UI/API. Public pages never probe it or accept a remote native capability override.

One costly browser job runs with one waiting slot. Byte/frame/memory preflight bounds simultaneous source/canonical Blobs, live PCM, transferred inputs, Go input/output/encoding buffers and returned results. Cancel terminates the active worker; terminal paths release the private Go heap. Main/worker/Go ABI checks reject stale modules before processing, and constant asset names retain no-store/revalidation behavior. Existing source receipts, DTO validators and latest-intent/revision checks remain authoritative.

Cloudflare serves only static app, WASM and qualified model files. Its Worker allows GET/HEAD, preserves exact native inline-script CSP hashes, COOP/COEP/CORP and WASM MIME, and resolves known dynamic HTML/RSC assets without an unknown-file/API HTML fallback. Model shards must be immutable, hash-verified and at most 16 MiB; trained browser inference remains unavailable. No Container or R2 user-audio path is part of this build. Bundled font/runtime notices remain under `/licenses/`.

The bounded [browser-local verification](browser-local.md#verification-status) has passed; final integrated CI/review and migration at `aurialis.yosefgamble.com` and `aurialis.yosef.app` remain open. Old production resources remain intact for rollback. Later HTTP/polling/DELETE descriptions refer to the native loopback path; the browser path uses the equivalent local job result directly.

GitHub branch protection is applied and independently confirmed: six repository CI checks plus app-bound GitGuardian, strict up-to-date branches, required PR/resolved conversations, administrator enforcement, no force push/deletion and zero required human approvals. This governs delegated integration; it does not establish feature or deployment acceptance.

## Library source lifecycle

Home processes selected, dropped or pasted WAVs sequentially through the existing CDR import. The browser checks finite byte/frame capacity; Go remains authoritative. Cancel or unmount aborts the active operation, removes any newly staged asset and retains finished projects. The first successful project opens after the queue settles, carrying partial-failure details.

`newAudioAssetId` issues immutable source keys; IndexedDB `add`, rather than overwrite, rejects a collision. A denied write can retain canonical audio in an aggregate session cache capped at 128 MiB plus 44 bytes. A full cache rejects further imports. Session audio survives navigation within the application but is lost on reload or tab closure. Library preview uses the same WASI controller and held-scrub hook as Master. Settings duplication makes an independent audio asset and a deep settings copy.

`WorkspaceLink` keeps supported same-origin workstation routes in one document through the native History API and a pathname subscription. This avoids static-export RSC navigation reloading the page and losing session audio for newly created project IDs. Modified clicks, new tabs, downloads, hash links and external or unsupported routes retain native browser behavior. Back/Forward updates the same shell; route changes update the title, focus its heading, scroll to the top and dispose the outgoing audio graph.

Source recovery compares canonical PCM hash, sample rate and frame count. Exact relink preserves settings and album membership. Explicit replacement validates the retained chain for the new rate, clears derived artifacts and commits a complete project record with an expected source revision and asset key. New source keys are staged before metadata changes. Old source keys remain as recovery copies, capped at 64, until project deletion: localStorage autosave does not acknowledge durability. Deletion waits for unshared active and recovery assets before removing metadata; a failed partial deletion leaves the project available for retry or source recovery. Hydration validates the new optional source metadata instead of trusting stored shapes.

## Measured analysis and compatibility foundations

`internal/mastering/features.go` hashes reconstructed PCM/layout, measures normalized short Hann spectra and aggregates one-second source features every 250 ms. FFT resolution scales from 1024 to 16384 samples so high-rate low bands remain useful. Spectral windows overlap by 75% with padded endpoints and constant squared-window coverage; original-sample RMS/stereo windows remain separate. Fractional bin overlap distributes band-edge power; spectral DC removal does not alter source samples or RMS. Neutral change points use robustly scaled energy/centroid/width novelty and shorter-window refinement, with eight-second separation. This is deterministic measurement, not musical-role recognition or a learned mastering model.

`SourceIdentityContext` validates canonical stereo PCM and hashes its sample-rate/channel/frame layout and interleaved Float32 bits without FFT analysis. The canonical bypass/32-bit import response includes this identity in its existing bounded source-metrics header, so relink can compare the same identity as Deep analysis without a second upload.

`KindAnalyzeFeatures` uses the bounded worker pool through `/api/analyze/features`. Its reservation includes decoded input and 16 MiB scratch headroom. Retained summaries are charged and deep-copied for snapshots, then released on DELETE or expiry. The Deep panel reads the original stored Blob, polls the native job states and displays measured bands/neutral intervals without changing processing settings. Cancel invalidates its UI generation immediately; the pending admission is retained solely to delete the actual job once its ID arrives. POST, polling and cleanup requests have independent bounded transport timeouts. No late result may replace a newer operation or another track.

The engine now declares algorithm 1 explicitly while preserving omitted/zero legacy settings. `LatencyFrames` reports buffered audio only (currently zero); `Drain` returns zero without altering destinations. WASM capability exports distinguish sonic algorithm IDs from control ABI counts. The integrated application negotiates 82 controls, appending algorithm 1 and rejecting unsupported versions atomically; the legacy 81-value interface remains supported. The worklet refuses an unrecognized capability or unaccounted nonzero latency. This adds no sonic v2 algorithm, artificial delay or lookahead limiter.

Advanced reuses a shared EQ-band control group for enable/type/frequency/gain/Q and a shared limiter-release control. High-pass retains gain for other filter types but offers no gain adjustment in sliders, pointer movement or Up/Down keys. All curve markers remain visible; only the selected band owns a 44 px drag target, avoiding overlapping touch targets. Band buttons and labeled fields provide equivalent selection and adjustment.

## Build and serving

`pnpm run build:binary` runs `scripts/build.sh`: compile `wasm/dsp` for `js/wasm` (offline preview) and `wasip1/wasm` with `-buildmode=c-shared` (live reactor), copy the matching Go `wasm_exec.js` for the offline module, run the Next.js static export and `scripts/sync-webui.mjs`, then compile `cmd/aurialis`. `internal/webui` embeds generated assets with `//go:embed all:embedded`. The native executable serves HTTP APIs and the frontend without Node at runtime.

`pnpm run test:binary` runs the executable from an empty directory, preventing source-tree assets from masking missing embedded files. The host serves embedded assets only; source-tree output cannot replace the embedded application. Generated assets are not committed, so a fresh `build:binary` is required for a usable application. Dynamic route IDs resolve to static exported shells and browser state supplies the project.

The default bind address is `127.0.0.1:8080`. The middleware emits COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, CSP, nosniff and frame denial headers. Host/Origin and Fetch Metadata checks protect localhost; these checks are not a remote multi-user authentication system.

### Stage activation history

A parameter change that stops a DSP module, EQ band or processing subpath clears that path’s history, including neutral settings that skip processing. Global bypass clears the suspended signal-stage histories. This prevents frozen state from replaying old audio after a long silent disabled interval while retaining unrelated running-stage history, coefficients, mid/side gain smoothing, monitoring calibration and dither state. Saturation model-local shaping history is cleared when leaving its processing path: the Crisp filter separately from the shared Tube/Tape/Transformer coloration filter. Switching between active saturation models retains the shared interpolation, antiderivative and DC histories. Constant-setting processing keeps the existing algorithms. This bounded state-lifecycle correction does not establish universally click-free switching or continuous interpolation of every control.

### Legacy offline typed-array boundary

The JS/WASM block and measurement entrypoints read intrinsic typed-array branding, backing buffer, byte offset and length rather than trusting object properties that a caller can shadow. All input and destination views are checked before DSP processing begins. Invalid block views return 0 and invalid measurement views return `{}` without advancing engine history; a subsequent valid block remains usable. A genuine one-element array with an own length of eight still processes as one element. Shared storage, nonzero view offsets, existing output alias ordering and numeric zero conventions remain covered. This prevents a genuine small Float32Array with a spoofed own length from causing the Go runtime to construct an oversized Uint8Array view. The live WASI numeric-control path is separate.

### DSP settings validation

Native rendering and the legacy JS/WASM bridge share `DecodeParamsJSON`. Supplied EQ arrays require five complete bands; supplied multiband arrays require three complete dynamics bands. The shape guards inspect every case-insensitive alias accepted by Go's struct decoder, including nested multiband keys. This prevents alternate casing from bypassing shape validation and silently truncating an oversized fixed array. Rejected bridge updates preserve active parameters and processing history. Identical duplicate JSON keys retain the decoder's existing last-value semantics. The numeric live WASI ABI uses its separate fixed-vector validation.

### Added DSP algorithms and limits

The processing order is input/legacy repair → EQ → optional De-Harsh → optional multiband → broadband compressor → saturation → stereo → sample limiter/output/dither. The user-facing repair workflow remains unavailable; De-Harsh is a separate stage.

- Auto release selects a signal-dependent recovery between the engine's 80 ms and 800 ms coefficients using a half-second memory. It ignores the stored manual release while active; compressor topology labels still do not select distinct hardware models.
- Mid and Side gains scale the encoded center/difference signals separately, alongside width and optional bass narrowing. The existing bass-narrowing filter remains its own implementation, not a validated Linkwitz–Riley specification.
- De-Harsh uses a stereo-linked band detector at the selected frequency, threshold-triggered attenuation and a requested maximum reduction. The detector is normalized by its Q after adversarial tests exposed excess attenuation. Transition and range results remain bounded by the tested signals; see the current checkpoint in tasks.
- Multiband uses complementary first-order low-pass splits: low is the lower low-pass, mid is the upper low-pass minus lower low-pass, and high is input minus upper low-pass. With unit band gains the sum reconstructs the input; independent linked-stereo gain reduction and makeup alter that sum. This is not a linear-phase or steep-isolation crossover, and processing overlapping bands can change phase and magnitude.
- Tube, Tape and Transformer are original bounded coloration models. Tube uses a biased nonlinear curve; Tape adds frequency-dependent softening; Transformer shapes a low-frequency path while retaining the remaining signal. Two interpolated substeps and antiderivative processing reduce some nonlinear artifacts but the averaging decimator is not a brick-wall filter. No alias-free, named-hardware or Waves-equivalent result is claimed. A coherent 32768-frame, 7001-bin tone at −6 dBFS measured a selected alias component near −71.4 dBFS for Tube/Tape at 10% drive and approximately −48.4/−49.4 dBFS at 50% drive, at both 44.1 and 48 kHz after warm-up. This one-tone result is not a broadband or all-drive alias specification. Saturation parameter updates rebase antiderivative history to the changed curve after adversarial tests exposed a drive-change spike; that repair does not imply every parameter is continuously interpolated. Clean leaves the saturation stage unchanged; legacy Warm/Thick/Crisp remain for existing sessions.

New controls enter the same Go core in native export and live/offline WASM. This source sharing is not sufficient evidence of live continuity, numerical parity or safe parameter transitions; the expanded fixtures and actual-browser gates are tracked below in [tasks](tasks.md).

## DSP and measurement boundaries

The Go engine implements gain, five EQ bands, optional De-Harsh and three-band dynamics, compressor, saturation, stereo processing and limiting. Compressor topology names currently share the same mathematics; the saturation characters are heuristic models. Mono-bass uses side-channel filtering that preserves the mono mid signal; it is not a validated textbook Linkwitz–Riley crossover. Current mathematical and safety tests establish particular transfer behaviors; they do not certify named hardware emulations, a Waves-equivalent chain, formal ITU/EBU conformance, or anti-aliasing performance. Limiter safety remains a sample-domain boundary; its streaming cubic interpolation is separate from the offline peak meter.

Live metrics are block-window sample peak dBFS, RMS, crest and correlation of the audible output, not whole-track LUFS or true peak. Controller silence readings use a finite −120 dBFS floor; the UI displays that as −∞ with no invented crest reading. Silence correlation is a defined convention, not evidence of stereo coherence. The API meter uses independent BS.1770/DeMan K-weighting, 400 ms windows at 75% overlap, an absolute −70 LUFS gate followed by a relative −10 LU gate, and a trailing three-second short-term interval. Shorter clips use their available duration for diagnostic reporting. The offline peak estimate uses a 49-tap, 4× Hann-windowed sinc interpolator with end padding. Fifteen external FFmpeg comparisons at 44.1/48/96 kHz reported at most 0.0542 LU loudness error and 0.0312 dB peak error for the selected fixtures; abrupt 8 kHz boundaries can differ by 0.58 dB. These are bounded fixture comparisons, not all-waveform guarantees or formal standards certification; the limiter has no validated true-peak/lookahead guarantee. The low-level `targetLufs` field remains metadata: Advanced rendering performs no implicit gain calibration. Simple mode explicitly measures output and adjusts an immutable input-gain snapshot toward its selected target, with bounded iterations and failure reporting when the target cannot be reached. See [`api.md`](api.md) for field limits. `pnpm run test:wasm` runs real compiled WASM/native parity fixtures; `pnpm run test:meters` runs independent FFmpeg meter comparisons. Both are wired into CI.

## Jobs, uploads and lifetime

`internal/server` handles bounded multipart requests and decodes audio in memory. User-supplied filenames do not become disk paths. Decoders accept mono/stereo PCM/float WAV and 16-bit PCM AIFF, rejecting multichannel input. AIFC and compressed formats are rejected; recognized compressed signatures are not evidence of decoders. Reconstruction emits new WAV samples and discards metadata. Signature checks inspect headers/metadata/trailers, never arbitrary PCM bytes; this is not steganography detection. Finite float-WAV headroom survives decode/export, while non-finite values are sanitized and integer exports clamp to full scale.

Five real user WAVs of approximately 35–47 MB each passed the single-request Brave import path. Returned canonical audio was approximately 76–95 MB with 798–805-byte measurement headers; first/last 256 converted frames matched, and cached reload produced actual destination output without another audio API request. Processing cancellation released admission in an observed 246 ms and response-transfer cancellation in 32 ms; retry succeeded in 13.203 s. Observed native RSS was 340,803,584 bytes (about 325 MiB). Earlier 676 MiB and 17–36.5 s baseline observations used different runs, so these are not controlled memory/speed comparisons or universal budgets.

`internal/jobs` owns measured-feature analysis, measured ScriptV2/Reference proposals, experimental legacy Deep analysis and heuristic separation queues and cancellation. The measured-feature API serves the Deep diagnostic panel; legacy script generation and heuristic splitting remain disconnected from enabled product workflows. Job decoded input, float output, encoded artifacts and scratch reservations are bounded at 256 MiB, retention at 64 records, and worker count at four. These are finite working/admission budgets, not a total RSS guarantee.
