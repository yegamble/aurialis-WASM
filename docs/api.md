## Measured source features

`POST /api/analyze/features` (alias `/analyze/features`) accepts one multipart `file` through the existing reconstruction and admission path. Options and query parameters are rejected. It returns the existing **202** job envelope with `kind: "analyze_features"`. Health advertises `featureAnalysisMethod` and `featureAnalysisVersion`. Poll `GET /api/jobs/{jobId}?wait=1`; the native status values are `queued`, `running`, `done`, `failed` and `cancelled`. A `done` response includes `features`, not a mastering script. `DELETE /api/jobs/{jobId}` cancels and releases retained summaries. Failed delivery of the admission response cancels that job.

`features.version` is `"1.0"`. Its `source` contains `pcmHash`, `sampleRate` and `frames`. SHA-256 covers little-endian uint32 sample rate, uint32 channel count 2, uint64 frame count, then interleaved little-endian L/R Float32 bits. This binds measurements to reconstructed stereo PCM and layout.

The five bands are 20–120, 120–500, 500–2000, 2000–6000 and 6000–20000 Hz. Each reports `lowHz`, `highHz`, `usableHighHz`, `bandwidthHz`, `powerDb`, `densityDbPerHz` and `valid`; unavailable bandwidth is explicit. Power is stereo-averaged mean square; unequal band widths are not interchangeable tonal targets. DC is excluded from spectral diagnostics while original RMS/stereo energy retains it. Normalized Hann FFT frames (1024–16384 samples, chosen by rate) use 75% overlap and padded endpoints with constant squared-window coverage, then aggregate into one-second windows at quarter-second hops. Raw RMS/stereo windows use original samples independently of spectral weighting. Very short sources use their available duration.

`frames` contains `centerFrame`, `rmsDb`, `centroidHz`, `sideMidDb` and `crestDb`. `windowCrestPercentiles` holds p10/p50/p90. `sibilanceRatioDb` is 6–12 kHz power relative to usable power at or above 20 Hz; it is neither a sibilance diagnosis nor a crest factor. Finite floors/conventions and bandwidth warnings accompany low-information signals.

`sections` partition the exact source-frame interval with neutral `Section N` names, `roleHint: "unknown"` and `confidence`. Confidence is a bounded novelty-strength heuristic, not a calibrated musical-role probability. Boundaries require eight-second spacing on sufficiently long sources; silence, constant fixtures and short clips can have one section. No EQ proposal, processing move, Verse/Chorus classification or trained-model claim is returned.

The job reserves decoded input plus 16 MiB analysis headroom; retained feature arrays are charged conservatively until cancellation/expiration. GET snapshots deep-copy mutable feature slices. The 512 MiB job budget, 64-job limit, worker timeout, retention, Host/Origin and upload bounds apply. Browser source analysis releases its admitted job after copying successful diagnostics, and deletes a known admitted job after Cancel. Cancel detaches the UI immediately even when the admission response is held; bounded transport failure falls back to server timeout/retention.

## DSP compatibility and capability foundation

The optional `params.algorithmVersion` accepts omitted/zero/one as unchanged algorithm 1 and `2` as the opt-in true-peak algorithm; null, fractional, negative and unimplemented values are rejected. Algorithm 2 is algorithm 1 with a lookahead limiter. When `limiter.enabled` and `limiter.truePeak` are set, it limits an 8× 48-tap Kaiser-windowed-sinc reconstruction to the ceiling minus 0.2 dB (plus the existing 0.995 linear margin), instead of estimating it. That detector is stricter than `truePeakDbtp`, whose 49-tap 4× filter can under-read content near Nyquist by more than 1 dB and can also over-read: on hot full-band noise in converted exports it has read up to 0.21 dB above the ceiling (see `sampleRate` below). The reported value therefore usually, not always, sits at or below the ceiling. Native offline renders compensate its latency, so output stays frame-aligned with the input and keeps its length. The sonic algorithm is independent of the numeric control ABI. Existing 81-value controls remain supported. The integrated browser negotiates ABI 2 and publishes 82 values in a 672-byte shared packet, appending an explicit algorithm ID through its separate buffer/setter; live playback publishes ID 2 (V1-10). Browser exports (WAV download, album render and its measurement, and the release check), the Equal-loudness A/B measurement and live playback all use `algorithmVersion: 2` with `limiter.truePeak: true`, both as `params` and inside a copy of the applied script's `chainParams`. There is no separate preview render: live playback is the preview.

Both WASM modules export `aurialis_control_count(abi)` (81 for 1, 82 for 2, zero otherwise), `aurialis_algorithm_supported(version)` (one for algorithms 1 and 2), `aurialis_latency_frames()` and `aurialis_live_drain()`. The appended interface uses `aurialis_control_buffer_v2` and `aurialis_set_controls_v2(count)`; invalid length/version rejects atomically. The worklet requires the published algorithm to be implemented and the current count to match, and reads `aurialis_latency_frames()` after every accepted transaction so it can read processed audio that far ahead of the dry ring (a latency above its alignment delay fails before warm-up). Native `LatencyFrames()` and `Drain()` return zero for algorithm 1. Algorithm 2 buffers `round(1.5 ms × rate) + 46` frames at every setting, bypass included (118 at 48 kHz), and `Drain()` flushes that tail once after the last input; live playback uses algorithm 2 and compensates that latency in the worklet. For algorithm 1, drain preserves destination contents and does not synthesize an IIR-decay extension. Transport alignment and filter phase are separate from buffered DSP latency.

## ScriptV2 foundation

Script schema `2.0`, schedule ABI `1` and sonic algorithm `1` are independent versions. The integrated Deep editor uses these interfaces for explicit source-bound Apply; their presence alone does not certify browser render deadlines.

The bounded foundation passed local native/API/compiled-WASI verification and the complete existing-UI browser regression. PR #8 merged at `d999f4e` after all six jobs in [CI run 39926912858](https://github.com/yegamble/aurialis-WASM/actions/runs/39926912858) passed on exact source `f29bc8c`, including 70 Linux browser cases. [Tasks](tasks.md#pr-7-and-pr-8-merged-scriptv2-foundation-verified) records source checkpoints and retained failures.

`POST /api/analyze/deep` and `/analyze/deep` accept multipart `file`, optional `profile` and `scriptVersion=2.0`. Omitting the version retains the legacy job. Version 2 returns a 202 job with `kind: "analyze_deep_v2"`; a successful snapshot contains `scriptV2` and `prediction`. `prediction.afterMetrics` is the measurement of that exact script rendered through the export algorithm (algorithm 2, true-peak limiter) at the source rate, before rate conversion or dither. `prediction.levelMatch` is `{gainDb, neededDb, limiterCapped}`: the loudness shortfall measured before the match (`neededDb`, source minus proposal LUFS), the gain the script applies as `chainParams.compressor.makeupDb` (`gainDb`) and whether the 2 dB limiter-reduction cap stopped it short. `prediction.compressorAverageGainReductionDb` averages the compressor's reduction over frames whose detector reads above −60 dBFS; `prediction.limiterPeakGainReductionDb` is the export limiter's largest reduction. All describe the final render, after the Level match. It is not part of the script schema. Existing polling, DELETE, timeout, admission and source-upload limits apply. Failed admission-response delivery cancels the admitted job. The job reserves decoded input plus 32 MiB headroom; retained scripts are charged at 2 MiB and snapshots deep-copy editable arrays.

The measured proposal uses neutral sections and a regularized fit against a smooth spectral trend, with uncertainty findings. It is a conservative heuristic, not musical-role or instrument recognition. Its explicit baseline uses algorithm 1, disabled repair, the sample-peak limiter and an Optical or VCA compressor with automatic release off ([recipes](mastering-controls-research.md#deep-proposal-baselines)). The compressor threshold is searched on the source so the render averages about 1.5 dB of gain reduction (0.75 dB for Dynamic & Open). It adds no hidden loudness normalization and no input gain, and its limiter ceiling is −1 dBTP. Its only loudness change is one measured Level match gain: the analysis renders the proposal through the export limiter, sets the loudness shortfall as compressor makeup (0.1 dB steps, at most +12 dB, and never so much that the export limiter's predicted peak reduction exceeds 2 dB), re-rendering up to three times until the prediction is within 0.1 LU of the source; the last render of the chosen gain is the prediction. The −1 dBTP ceiling is held by the export limiter, not by the Level match. Generated section moves are capped at +0.8 dB EQ, +8 width points and +0.5 dB saturation drive above the baseline; the generator currently emits only −0.5 dB input-gain trims, so the caps guard future EQ, width and drive moves. Findings explain a predicted loudness rise above 1 LU, a crest-factor cut above 4 dB or an export limiter peak reduction above 4 dB (`warning`), and a loudness drop above 1 LU (`info`). When the 2 dB limiting cap stopped the Level match, the drop finding says so: holding the source loudness would need more than 2 dB of limiting, and the level should be raised by hand only if the extra limiting sounds clean. The legacy version 1 job applies the same loudness and crest findings to its own render.

**Deprecated louder routes.** The legacy `/api/analyze/deep` job (no `scriptVersion`) and `profile=` on `/api/master/render` still use the version 1 `ProfilePreset` recipes, which add up to 7.5 dB compressor makeup (plus up to 1.5 dB input gain) before a −1 dBTP limiter. A `profile=` render names no algorithm, so it renders with algorithm 2 and `limiter.truePeak` and delivers at most −1 dBTP like UI exports (a `params` overlay may still choose otherwise). Explicit algorithm 1 `params` or scripts (including a ScriptV2 posted as Analyze returned it) keep the sample-peak limiter, which has no true-peak guarantee: the dense QA source read −0.98 dBTP and a synthetic inter-sample fixture more than 1 dB over the ceiling. Send algorithm 2 with `limiter.truePeak`, as UI exports do, for a −1 dBTP delivery. They are kept for compatibility, carry the loudness findings, and are deprecated; the integrated UI uses neither.

The script contains `version`, `source`, `revision`, canonical `profile`, `summary`, `sections`, `moves`, `findings`, `chainParams` and `beforeMetrics`. `source` uses the canonical PCM identity documented above. Sections partition the complete source using integer `startFrame`/`endFrame` values and neutral `roleHint: "unknown"`. Revisions are integers from 1 through 2^53−1. Unknown, duplicate, case-aliased, missing required or null JSON fields are rejected; JSON is capped at 2 MiB. There are at most 128 sections, 128 findings and 128 moves, each with 2–256 strictly increasing points. A move contains a unique `id`, valid `sectionId`, bounded `reason`, `target`, `operation` (`absolute` or `add`), `points` (`frame`, `value`), `fadeFrames` and `muted`. Same-target intervals cannot overlap. Intervals are half-open; fades fit half the interval and at most 100 ms.

| Target | Absolute range | Evaluation |
| --- | --- | --- |
| `inputGainDb` | −36…36 dB | Every sample before processing |
| `eq.0.gainDb` through `eq.4.gainDb` | −24…24 dB | Held cells; maximum 0.1 dB parameter variation |
| `compressor.thresholdDb` | −80…12 dB | Held cells; maximum 0.1 dB variation |
| `compressor.ratio` | 1…100 | Held cells; maximum 0.01 variation |
| `saturation.amount` | 0…100 | Held cells; maximum 0.1 percentage-point variation |
| `stereo.widthPct` | 0…200 | Every sample at the stereo stage |

An `add` move is resolved once against the explicit baseline. Gain and width use an exact rational source/device clock. Other targets use the absolute device lattice `max(1, floor(deviceRate / 1000))`; curves and fades exceeding the declared cell error are rejected with an instruction to extend fades or reduce changes. These are parameter-error limits, not universal acoustic tolerances. Automation does not enable modules; bypass and disabled stereo retain their normal semantics. Repair targets and enabled repair baselines are rejected by ScriptV2 validation, as is an enabled true-peak limiter unless `chainParams.algorithmVersion` is 2.

`POST /api/master/render` and `/master/render` accept a multipart text field `script` containing the complete ScriptV2, mutually exclusive with `params` and `profile`. Native rendering hashes actual reconstructed PCM and rejects a different source, then runs the common evaluator at the source rate. Existing WAV/JSON output and bit-depth options apply; 16/24-bit output selects corresponding dither. Invalid scripts or identities return 400, oversized fields 413 and cancellation 408.

`POST /api/automation/compile?deviceRate=48000` accepts only `application/json` ScriptV2, up to 2 MiB. The optional integer rate defaults to the source rate; both rates must be 8000–192000 Hz. No root alias exists. Its 200 JSON response contains `version: "1.0"`, `source`, `revision`, `deviceRate`, `quantumFrames`, `baseline`, numeric `moves`, `targets` and **`sourceVerified: false`**. It validates declared identity and layout without receiving audio; the host must bind authoritative actual-source metadata before playback. Compilation shares the single POST admission slot and 60-second request timeout. Invalid content type/query/script returns 400, excess body 413, cancellation 408 and busy admission 503.

The numeric WASM interface advertises `aurialis_schedule_abi() == 1`. Its 11-value source buffer contains ABI 1, source rate, frame count and eight big-endian SHA-256 uint32 words. `aurialis_schedule_bind_source` accepts a new host-supplied identity only while detached; binding the same identity is idempotent even while attached. It does not hash browser PCM. `aurialis_schedule_begin(revision, count, deviceRate)` reads the separate 82-value algorithm-1 baseline and stages an inactive slot. Each `aurialis_schedule_stage_move(index)` call copies at most 256 points from the 516-value move buffer: target index, point count, fade frames, muted 0/1, then frame/value pairs. `aurialis_schedule_commit` publishes the complete baseline and revision atomically; `aurialis_schedule_revision` acknowledges it. Stale or invalid publication preserves the active revision. Static JSON/numeric setters and band edits reject while attached. The integrated browser stages them through the publication protocol below; retained kernel and browser acceptance evidence remain separate.

Bind before the source starts: every processed device frame then advances an independent rational source clock, including static/bypassed playback. First Apply and later revisions inherit its exact phase. Hosts submit no processing frames during hold/pause. Initial or changed-source binding starts phase zero without resetting DSP history; same-source binding preserves both. `aurialis_schedule_seek` works while detached or attached, reconstructs source-zero phase and resets DSP history; invalid seeks preserve state. `aurialis_schedule_set_looping` works in either state and retains fractional overshoot without resetting DSP history at wraps. `aurialis_schedule_detach` restores the explicit baseline while preserving phase for later reapply. `aurialis_live_reset` seeks zero while retaining bound identity, loop policy, attachment and accepted revision. Binding a different source requires detach. No ABI signature changed for this correction.

### Integrated browser workflow

Replacing any existing Deep draft first opens a shared confirmation dialog. Keep draft/Escape starts no POST and preserves edits; confirmation rechecks the complete track, proposal and selected profile before analysis. Applied processing stays selected until a separately acknowledged Apply. The Deep panel requests a measured proposal using one of `Warm Analog`, `Punchy Commercial`, `Dynamic & Open`, `Vocal Forward` or `Bass Heavy`. The client validates a closed bounded DTO, then asks the Go compiler to validate the complete schedule and target metadata. This remains heuristic neutral-section analysis; generated roles stay unknown. Manual moves expose exact source frames, values, fades, additive/absolute operation, reset/delete and mute. Solo filters the submitted applied snapshot only; authored draft moves stay intact. Editing, mute and solo require explicit Apply before changing sound or export.

`Track.deepMastering` stores `sourceRevision`, `proposal`, `targets` and optional `applied`/`before`. The controller verifies the loaded canonical Blob’s SHA-256 identity before binding or publication. Compilation still returns `sourceVerified: false`; the browser independently verifies the actual Blob, and native render rehashes actual PCM. Source replacement invalidates Deep state; identity-preserving relink retains it while advancing the source revision. Hydration validates the complete saved shape and reports invalid metadata rather than silently applying it.

Apply prepares fixed numeric buffers outside the sample loop. The worklet stages at most one move of at most 256 points per quantum into an inactive slot, reports staged, then commits only after the host rechecks source/settings/applied revision. An acknowledgment and matching compare-and-swap publish the accepted state to playback/export. Pending baseline edits are debounced for 100 ms into a complete new baseline/schedule transaction; the previous acknowledged snapshot remains selected until success. A canceled or stale precommit preserves it. Uncertain postcommit acknowledgment pauses and rebuilds playback from the selected revision; it does not continue ambiguous audio.

Source start first waits for an arm acknowledgment, then shares a future 128-frame-aligned device epoch. A 24-byte sequence-protected buffer holds generation and safe-integer start/end device frames; Infinity means no end deadline. Native-source and Go looping are fixed when the epoch is armed. Finite epochs use zero exterior and retain all valid delayed output through the integer audible deadline. Enabling Repeat during a finite pass drains it, then prepares a clean epoch if still requested; it does not promise a seamless transition. Disabling Repeat during a periodic epoch retains its periodic source conversion and publishes the next input-cycle audible deadline; reenabling removes that deadline. This drains the existing alignment ring, not an invented DSP-decay tail. Go owns rational phase, envelopes and loop evaluation; TypeScript neither evaluates envelopes nor resamples audio. Pause submits no frames, seek resets the Go history/source epoch, and native AudioBufferSource resampling supplies actual device input. Detach returns to the applied static baseline; Revert restores the full first-Apply settings snapshot. Both retain the draft. Master live playback, individual export, Library preview and release diagnostics use the acknowledged applied script. Target-loudness and album normalization require Detach first.

The full draft/applied JSON is persisted without truncation. Quota failure leaves the prior durable record and displays session guidance; validated draft and applied Script JSON downloads provide backups. These downloads do not provide a script-import UI. Browser evidence and outstanding gates are recorded in [tasks](tasks.md#integrated-deep-editor-and-live-schedule).

## Measured Reference proposals

`POST /api/analyze/reference` accepts multipart audio parts `source` and `reference`, optional `params` (up to 64 KiB, existing DSP validation, native defaults when omitted) and optional `options` (up to 2048 bytes). There is no root alias. Both files pass the in-memory CDR boundary and retain raw canonical source identities. The combined multipart body shares the existing 257 MiB maximum (`maxUploadBytes`), including metadata and boundaries; adding a reference does not double that limit. Each file keeps the 268,435,500-byte file cap and the 33,554,432-frame decode bound. Query parameters, duplicate/unknown parts and invalid file dispositions are rejected.

Options default to `amount: 0.5`, `protectBelowHz: 120`, `includeWidth: false` when the field is omitted. Supplied options require finite `amount` in 0…1 and `protectBelowHz` equal to 0 or 120; optional `includeWidth` is boolean. Unknown, duplicate, case-aliased, missing required or null option fields are rejected. The browser's 0…100% amount control converts to the API fraction.

Admission returns 202 with `kind: "analyze_reference"`; poll the existing job route for `referenceProposal`. Existing DELETE/expiry, authority/Origin checks, single POST admission and two-minute worker timeout apply. Both decoded inputs are reserved together under the manager lock: `source.frames × 8 + reference.frames × 8 + 32 MiB`, within the shared 512 MiB job budget and 64-record limit. Results are bounded/charged at 32 KiB, snapshots deep-copy warnings/optional width metadata, and cancellation clears the retained proposal. These are working/admission bounds, not a process RSS guarantee. Failed admission-response delivery cancels the job.

`referenceProposal.version` is `"1.0"`; `sourceSpectrum` is **`"baseline_rendered"`**. `source` and `reference` identify the raw canonical PCM. `baseline` is the exact submitted chain; `params` is its proposed replacement. `options`, five `bands`, residual/guard diagnostics, optional `width` and `warnings` describe the estimate. Each band reports `lowHz`, `highHz`, `sourceDensityDb`, `referenceDensityDb`, `targetDeltaDb`, `predictedDeltaDb` and `included`. Common edges are 20/120/500/2000/6000/20000 Hz clipped to the lower Nyquist. Unavailable or insufficient-energy bands are excluded; fewer than three audible common bands produces no tonal correction. Spectra remove DC and use normalized overlapping Hann powers; source measurements include its complete baseline chain, while the reference uses original reconstructed audio. Overall common-band level is normalized for tonal comparison; input gain and loudness targets remain unchanged.

The regularized fit changes only enabled non-high-pass EQ gains, by at most ±3 dB per knob, while numerically checking the actual summed TPT response for at most 3 dB added positive peak. Band frequencies, Q, filter types, enable flags and unrelated chain parameters are preserved. Amount zero retains the exact baseline; bypass/Original and disabled modules remain authoritative. The optional 120 Hz protection checks predicted 20–120 Hz response and complete rendered band-energy change within 0.25 dB. These numerical/source-specific checks are not hardware certification.

Optional width is limited to ±20 percentage points times amount, within 0…200%; it never enables stereo or invents absent stereo energy. Rendered correlation must remain at least 0.1 for a changed width. Width diagnostics include before/after width, Side/Mid energy, correlation, sample peak, `applied` and `reason`.

Every final candidate is rendered through the complete chain. Up to eight bounded attempts halve only the permitted EQ/width deltas; accepted output must not worsen the level-normalized common-band mismatch beyond a 1e-9 dB arithmetic allowance, and must meet enabled bass protection. Exact baseline is the fallback. Erased audible output cannot earn a better score; its internal invalid-candidate sentinel is never retained in JSON. `beforeOutputResidualDb`/`afterOutputResidualDb` measure actual full-rendered mismatch. The separate `beforeResidualDb`/`fitResidualDb` describe the linear EQ-contour fitting objective and must not be presented as final output quality. Predicted boost/protection and `remeasuredProtectedDeltaDb` are diagnostics; `protectionVerified: false` can identify an unchanged baseline. Final LUFS, reconstructed peak and perceptual similarity remain separate checks.

The browser verifies both loaded canonical Blobs against SHA-256 source receipts before and after analysis, validates exact baseline/options and permits only bounded EQ/opt-in-width deltas. Apply uses a complete-record compare-and-swap for the reviewed source/reference and current settings. Amount changes and repeated Apply use the same original session baseline. Session Revert restores the original settings and starting mode/shortcut metadata only while the applied settings remain current. The UI acknowledges the reducer’s accepted settings before validating session ownership, so an Apply during the commit-to-effect interval does not discard Revert. A reference-only compare-and-swap rejection clears the pending state, preserving competing settings and allowing fresh analysis. Success requires a new track record with the accepted settings, so an unchanged repeated Apply cannot conceal rejection. This changes no endpoint, proposal, processing parameter or loudness behavior. Changed sources/settings invalidate the review; attached Deep automation requires explicit Detach before a static proposal. Both successful and canceled jobs are released through the shared bounded job helper. Older sources without verified identity require Library restore/reimport.

## Security and resource contract

The executable binds only to loopback IPs (default `127.0.0.1:8080`). `AURIALIS_ADDR` takes precedence over `PORT`, then `-addr`; a numeric `PORT` becomes `127.0.0.1:<port>`. The request Host must match an allowed local authority and the actual port. A supplied Origin must be HTTP with the same authority; `null` is rejected. Fetch Metadata permits only `none` or `same-origin` when supplied. Rejections return 403 JSON. These checks do not provide remote authentication.

Responses carry COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, and a CSP restricted to same-origin assets with hashes for the embedded bootstrap scripts. WASM uses `application/wasm`. Browser fonts are self-hosted. `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()` denies unused device and payment access; WAV download responses also carry a sandbox CSP. The Cloudflare Worker sends the same `Permissions-Policy` and adds `Strict-Transport-Security: max-age=63072000; includeSubDomains` (two years, no `preload`). The loopback executable serves plain HTTP and sends no `Strict-Transport-Security`.

Multipart bodies are capped at **257 MiB including overhead** (`maxUploadBytes: 269484032` in `/health`). The audio file is capped at **268,435,500 bytes** (`maxAudioFileBytes`; a maximum stereo-float WAV including its 44-byte header); the browser uses the same file-byte cap, allowing 256 MiB of stereo-float samples plus the canonical header. `-max-upload-bytes` / `MAX_UPLOAD_BYTES_OVERRIDE` (a positive integer environment value wins over the flag) can lower the request cap, never increase it: a value above 269,484,032 stops startup with `maximum upload must be between 1 and 269484032 bytes`. A cap below 268,435,500 also lowers `maxAudioFileBytes` to the same value. Decoding permits **33,554,432 frames**: about 699 seconds at 48 kHz or 349.5 seconds at 96 kHz; byte limits can shorten this. Canonical float re-upload fits the multipart limit.

One expensive POST upload/render is admitted at a time. Another receives **503 busy**, with `Retry-After: 1`, before its body is read. A maximum-length export can hold that single slot for up to 10 minutes (its export budget ceiling), so 503 busy can persist that long. Worker jobs reserve decoded input, float output, encoded artifacts and scratch headroom within **512 MiB**, retain at most **64 jobs**, and return **503 queue_full** when admission fails. Automatic mode starts the smaller of two workers or the available logical CPU count; explicit worker counts are capped at four. The reservation is a job working budget, not a process RSS guarantee. A separate single-request frame/body bound limits synchronous scratch. Representative native 3/5-minute tests and observed memory belong in the task tracker; browser and arbitrary workload memory are not certified by those probes. Worker timeout is two minutes; terminal artifacts expire after 15 minutes, checked every minute.

Every admitted POST runs under a **60-second** base deadline covering upload, decoding and validation, and its body must arrive within a read deadline of 10 seconds plus 1 second per 8 MiB of `Content-Length`, capped at 60 seconds (a chunked body without `Content-Length` falls back to the server's 60-second read timeout), so a slow small body is cut off quickly. Once `/api/master/render` or `/master/render` has validated its export, the base deadline is replaced by a work budget measured from that point: 60 seconds plus 2 µs per source frame plus, when converting the sample rate, 8 µs per converted output frame, capped at **10 minutes**. The two largest shapes need about 6 minutes (16,777,216 frames at 48 kHz → 96 kHz: 362 s; 33,554,432 frames → 44.1 kHz: 374 s). The connection write deadline is extended to the budget, and the WAV body then gets 10 seconds plus 1 second per 8 MiB. The export holds the single POST admission slot throughout. Closing the client connection cancels the work. An export that exhausts its budget returns **408 `export_timeout`** whose `detail` names the stage and budget and asks for a shorter range, a lower sample rate or the source rate; a body that misses its read deadline returns **408 `upload_timeout`** ("The upload was too slow and timed out; retry, or export from a less busy machine or connection"), and a client cancellation or an upload that outlasts the 60-second base deadline returns 408 `canceled`.

Uploaded names are validated and never used for host disk writes. Parsing/decoding stays in bounded memory. Only mono/stereo input is supported; multichannel input is rejected. Supported inputs are WAV PCM 8/16/24/32-bit integer or 32-bit float, including `WAVE_FORMAT_EXTENSIBLE` (PCM or float sub-format GUID, valid bits within the container), AIFF integer PCM of 1–32 bits, AIFF-C `NONE`, `sowt` (16-bit little-endian) and `fl32` (32-bit float), native FLAC (mono/stereo, 4–32-bit, 8–192 kHz) and MPEG-1/2 Layer III MP3. Detection uses magic bytes after any ID3v2 tags, never the filename. FLAC frames must pass header CRC-8, frame CRC-16, STREAMINFO channel/rate/depth agreement, declared length and (when present) the audio MD5. MP3 must form an exact chain of at least two same-rate frames; Xing/Info/VBRI frames are dropped and LAME/Lavc encoder delay and padding are trimmed. ID3v2, FLAC metadata blocks, ID3v1 and APEv2 tags are scanned for payload signatures and discarded; more than 64 other bytes after the last frame are rejected as a polyglot. Decoded MP3 keeps float overs above full scale. Compressed AIFF-C (for example µ-law), OGG, M4A/AAC, MPEG-2.5 and free-format MP3 are unsupported. WAV checks include declared RIFF length, alignment, byte rate, chunk bounds, duplicate chunks and whole frames. Reconstruction creates new samples without metadata. Executable/archive/script signatures are inspected in headers, metadata and outside-container trailers, not arbitrary PCM bytes. Legitimate sample bytes can match those signatures. Reconstruction is the audio-only boundary; this is not PCM steganography detection or a universal malicious-content guarantee.

Errors use JSON with `error`, `detail` and numeric `status`. Malformed fields/container/params return 400, oversized requests 413, rejected authority/origin 403, missing resources 404, exhausted deadlines or cancellation 408, admission failures 503, and encoding failures 500.

### Rendering

Send `multipart/form-data` with required `file` and optional fields:

- `profile`: `Warm Analog`, `Punchy Commercial`, `Dynamic & Open`, `Vocal Forward`, `Bass Heavy`; compatibility aliases include `indie_warmth`, `modern_pop_polish`, `pop_punk_air`, `hip_hop_low_end`, `metal_wall`.
- `params`: JSON overlay on default/profile DSP parameters. Unknown fields, nulls, trailing JSON, invalid enums, non-finite/out-of-range values and non-five-element `bands` arrays return 400. `limiter.ceilingDbtp` accepts −24 to −1 dBTP on every route (`params`, `profile`, a ScriptV2 `chainParams`, the browser worker and the WASM bridge), whether or not the limiter is enabled; a higher ceiling returns 400 `invalid_params` whose `detail` names the field and range (V1-09). Other out-of-range settings return the same field-and-range detail, and a known field with the wrong JSON type names the field and type (for example `limiter.ceilingDbtp must be a number` for `"-0.5"`); malformed JSON keeps the generic `Invalid DSP params JSON`. EQ band types include `low_shelf`, `peaking`, `high_shelf`, and actual `high_pass` processing. Parameters include `bypass`, `abOriginal`, `inputGainDb`, `eqEnabled`, `bands`, `compressor`, `saturation`, `stereo`, `limiter`, `repair`, `deHarsh`, `multiband`, `ditherBits`. `compressor.topology` is `optical`, `vari_mu`, `fet` or `vca`; each selects its own detector, transfer curve and release behavior (see [architecture](architecture.md#added-dsp-algorithms-and-limits)). The models are behavioral, not hardware emulations. The retired `loudnessMatchAb` field (V1-11) is accepted only as `false`, so settings and scripts saved earlier still decode; `true` returns 400 naming the field. Responses no longer include it.
- `bitDepth`: `16`, `24` (default), or `32`; other values return 400. 16/24-bit PCM receives TPDF dither and clamps to integer full scale (encoding uses the same 2^(bits−1) scale as decoding, so on-grid samples round-trip bit-exactly and +1.0 clips to the largest positive code; a final ceiling correction truncates dithered samples back onto their grid); 32-bit float decode/export preserves finite headroom above ±1. NaN and infinity are sanitized to zero. Processing can change source levels; bypassed float round-trips preserve headroom.
- `sampleRate` (optional, render endpoints only): exactly `44100`, `48000`, `88200` or `96000`. Any other text, including `0`, signs, leading zeros, decimals, exponents and surrounding whitespace or line breaks, returns 400 `invalid_sample_rate`; a repeated field returns 400 `invalid_multipart`. Other upload endpoints reject `sampleRate` and `dither` as unknown fields (400 `invalid_multipart`). Omitted, empty or equal to the source rate leaves the export byte-identical to an unconverted one. Otherwise the render runs at the source rate without dither, then `dsp.ResampleContext` converts it with a rational polyphase Kaiser-windowed sinc (120 dB stopband, flat to 90% of the lower Nyquist frequency, group delay removed, duration kept and rounded up to a whole frame). `dsp.FinishResampled` then finishes the audio at the delivery rate: with `limiter.enabled` (and neither `bypass` nor `abOriginal`) it runs the algorithm 2 true-peak lookahead limiter there, whatever `limiter.truePeak` and `algorithmVersion` say, latency-compensated so length and alignment are kept. That limiter holds its 8× reconstruction at the ceiling minus 0.2 dB (plus the 0.995 linear margin) with a ramped gain, so the delivered true peak stays at or below the ceiling without clipping samples. Then the requested dither is applied, last and once. With the limiter off, levels are untouched, as in an unconverted export: 32-bit float keeps overs, and 16/24-bit output only meets the integer full-scale clamp. `afterMetrics`, `sampleRate`, `frames` and `duration` describe the delivered audio. `afterMetrics.gainReductionDb` adds the delivery limiter's final reduction to the render's. `afterMetrics.truePeakDbtp` (and `X-Aurialis-After-Peak-dBTP`) is the 49-tap 4× meter described below, which is less accurate than the limiter's detector. On hot full-band noise it has read up to 0.21 dB above the ceiling at 96 to 88.2 kHz, and 0.004 dB above it at 44.1 to 48 kHz. In the same tests (a −1 dBTP ceiling, all 12 rate pairs, `limiter.truePeak` on and off), the 8× detector read −1.243 to −1.244 dBTP, an independent 32× 128-tap reference read −1.173 to −1.229 dBTP, and no sample reached the ceiling.
  - Limits, checked before rendering (400 `invalid_export_options`): the converted output may not exceed 33,554,432 frames, so a converted track can last at most 12:40.87 at 44.1 kHz, 11:39.05 at 48 kHz, 6:20.44 at 88.2 kHz and 5:49.53 at 96 kHz, whatever the source rate (for example, a 44.1 kHz source can be up to 5:49.53 long when converted to 96 kHz). A source rate outside 8–192 kHz, or whose reduced ratio to the target has a numerator or denominator above 4096, is rejected ("too complex" for the latter). 44056 Hz to 48 kHz reduces to 6000/5507 and is one example. All common rates (8, 11.025, 16, 22.05, 32, 44.1, 48, 88.2, 96, 176.4 and 192 kHz) convert.
- `dither` (optional, render endpoints only): exactly `tpdf` (default; empty also means `tpdf`) or `none`; any other text, including surrounding whitespace, returns 400 `invalid_export_options`. `none` leaves 16/24-bit output undithered (rounded to the grid by the encoder) for material that is already dithered. It has no effect on 32-bit float, which keeps any `params.ditherBits` exactly as before. The JSON `params.ditherBits` reports the dither the delivered file carries: the bit depth for TPDF-dithered 16/24-bit output, including converted exports that dither after conversion, and 0 with `dither=none`. The browser worker accepts the same two fields and the same validation, and its converted exports match the native render byte for byte.
- `format=json`, or `Accept: application/json`: return `status`, `sampleRate`, `frames`, `duration`, `bitDepth`, `params`, `beforeMetrics`, `afterMetrics` instead of audio.

Supplied `bands` arrays require exactly five complete EQ objects; supplied `multiband.bands` arrays require exactly three complete dynamics objects. Case variants such as `Bands`, `Multiband` and nested `BANDS` receive the same array validation. Every differently cased alias supplied in one object must satisfy those count and completeness checks. Numeric ranges are validated on the final decoded settings after alias resolution. Identical duplicate JSON keys retain the decoder's existing last-value behavior. Rejected settings return 400 without applying the update.

WAV output uses `Content-Type: audio/wav`, `Content-Disposition: attachment; filename="aurialis-mastered.wav"` and compatibility headers `X-Aurialis-Before-LUFS`, `X-Aurialis-After-LUFS`, `X-Aurialis-After-Peak-dBTP`. Rendering preserves the uploaded sample rate and frame count unless `sampleRate` converts them. The browser worker transport (`deviceAudioRequest`) sends no LUFS headers, but sets `X-Aurialis-After-Peak-dBTP` (two decimals, as natively) from the render's `afterMetrics.truePeakDbtp`; the Export dialog reads this header to show the delivered true peak in its status line. Metric fields are `integratedLufs`, `shortTermLufs`, `truePeakDbtp`, `samplePeakDbfs`, `dynamicRangeDb`, `correlation`, `lowBassCorrelation`, `dcLeftDbfs`, `dcRightDbfs`, `clippingSamples`, `gainReductionDb`; see the measurement limitations below.

For an audio response with `params.bypass=true` and `bitDepth=32`, the server additionally sends `X-Aurialis-Source-Metrics`: at most 4096 bytes of JSON containing `sourceIdentity`, `sampleRate`, `frames`, `duration`, `beforeMetrics` and `afterMetrics`. The identity has `pcmHash`, `sampleRate` and `frames`, using exactly the canonical SHA-256 byte layout described under measured source features. It is computed without FFT analysis and remains stable through canonical float-WAV reconstruction. Both metric objects describe the reconstructed source and use the schema above. The server measures this bypass source once and reuses its decoded samples instead of running the enabled-DSP render path. WAV responses declare their exact `Content-Length`. This changes neither CDR validation nor request, frame, admission or timeout limits.

The browser import uses this single response instead of separate measurement and reconstruction POSTs. It rejects missing, oversized or invalid measurement headers, cancels an unusable response body, checks canonical byte size (`44 + frames × 8`), then validates the decoded sample rate and frame count against the header. These checks describe transfer consistency; they do not replace the authoritative native decoder.

```bash
curl --fail-with-body http://127.0.0.1:8080/api/master/render \
  -F file=@source.wav -F 'params={"inputGainDb":-6}' \
  -F bitDepth=24 -o mastered.wav

curl --fail-with-body http://127.0.0.1:8080/api/master/render \
  -F file=@source.wav -F 'params={"bypass":true}' -F format=json
```

Release adds no HTTP route. The client sends the same render request as Export (`renderDelivery`: `params` or the acknowledged applied ScriptV2, `bitDepth`, and the optional `sampleRate` and `dither` fields of the chosen delivery format), then bypass-measures the **returned encoded WAV** through the existing render/measurement interface. This includes conversion, final quantization and dither. Source identity is checked against the actual loaded canonical Blob before and after processing; the returned file must have the delivered rate and length (the source frames, or `ceil(frames × rate ÷ sourceRate)` after conversion) and matching duration. Album masters send the same request with the album's delivery format. The separate device-local worker adapter must preserve these same operations without remote audio HTTP.

The version-1 saved report contains `createdAt`, `title`, `platform`, `source`, `sourceRevision`, `scriptRevision`, `bindingHash`, `processingHash`, `output` and the eleven `metrics` fields. `output` records SHA-256, byte length, stereo layout, delivered rate, frame count, bit depth, encoded full-scale frames and leading/trailing quiet frames at a −60 dBFS threshold; those counts describe the delivered file, so hydration bounds them by its frame count, not the source's. `dither` is `"tpdf"` or `"none"` (32-bit float carries none); a report saved before it existed restores as TPDF for 16/24-bit. Binding covers the track/source key and revision, bit depth, a converted rate or disabled dither, current parameters and the entire acknowledged applied script, including its points; a source-rate dithered check keeps its earlier binding. Processing identity hashes that script or the static parameters with the same delivery fields. A source, processing or delivery format change invalidates the report; profile changes reuse measurements with different guidance.

The client validates an exact clean 44-byte stereo WAV header and its layout/length at the delivered rate, finite samples, 16/24-bit PCM or 32-bit float, and existing frame/rate bounds. A saved converted report must name a supported export rate and the converted frame count. Encoded metadata copies only verified layout fields; the original source's `pcmHash` remains in the separate source receipt. The encoded WAV has its own SHA-256. Full-scale counts describe encoded samples; they do not establish the cause of clipping. Saved-report hydration rejects malformed records and serialized JSON longer than **16,384 characters**. Saving uses a complete-track-record compare-and-swap; cancellation, stale source/settings/encoding and unmount cannot publish a late report.

The UI claims expected canonical-source/hash and output memory before IndexedDB loading. `collectReleaseReview` takes that same owner, retains the original source through final verification, charges full-buffer inspection/WebCrypto copies and transfers exact WAV-byte ownership to its returned artifact. Consumers must call its idempotent `dispose()` on discard. Pending cancellation retains source-load claims until the awaited operation settles; replacement attempts overlap the old retained artifact. Stale results, errors, changed bindings and unmount release their own artifacts. JSON reports and audio DTOs contain no ownership handle.

Only the session artifact can download the measured WAV, and repeated downloads reuse the same Blob without rerendering. A saved report restores JSON metadata after reload, never audio-download authority. Exported JSON also records policy source/scope, the policy check date and limitations. No output gain, automatic repair, trimming or resampling is part of review.

### Experimental jobs and script schema

Deep analysis accepts `file` and `profile`. Separation accepts `file` and `stems=2|3|4|5|6`, with legacy model aliases such as `htdemucs` mapping to four outputs and `htdemucs_6s` to six. Every alias runs the same trained five-head BS-RoFormer (Mega53 subset). Stem IDs in order are 2: `vocals`, `instrumental`; 3: `vocals`, `drums`, `rest`; 4: `vocals`, `drums`, `bass`, `other`; 5: `vocals`, `drums`, `bass`, `melody` (guitar + piano), `other`; 6: `vocals`, `drums`, `bass`, `guitar`, `piano`, `other`. The last stem is the source minus the others, so stems sum to the mix within float32 rounding. Stems download as 24-bit WAV at the source rate and are retained like other job results (15 minutes).

Separation runs one job at a time on its own queue with a 90-minute limit and a 1.5 GiB memory pool separate from the 512 MiB job budget; up to four more wait. The reservation is the separator's working memory, the input copy and the float stems. ## Measurement limits and verification

Live playback shows two meter strips. **Live loudness** comes from a streaming Go meter (`dsp.LoudnessMeter`) inside the WASI reactor, reading the processed output before A/B mixing and monitor volume: momentary (400 ms) and short-term (3 s) LUFS, gated integrated LUFS and EBU Tech 3342 loudness range since playback started, a 4× true-peak hold plus the latest 50 ms peak, the largest compressor + limiter gain reduction in that interval, and correlation. Integrated and range use 0.05 LU histograms, so values can differ from the offline meter by up to about 0.05 LU. Windows that are not yet full show "—". The reactor exports `aurialis_meter_buffer` (seven Float64 values) and `aurialis_meter_snapshot`. **Measured audio levels** are computed in the worklet from actual audible blocks: sample peak dBFS, stereo RMS and crest factor. The 4096-point spectrum averages L/R power and describes the monitored processed/original selection. Measurements arrive at up to 20 Hz; animation-frame interpolation changes the drawn transition between measured traces, not the underlying measurements. These values are separate from full-track API diagnostics. Release review bypass-measures the exact selected encoded WAV; an attached Deep script supplies the acknowledged applied settings. The API meter uses BS.1770/DeMan K-weighting with 400 ms windows and 75% overlap, absolute −70 LUFS and relative −10 LU gates, and a trailing three-second short-term interval. Short clips use the available duration, which is a diagnostic approximation to standard-duration reporting. Silence reports a finite −70 LUFS floor. Offline `truePeakDbtp` uses a finite 49-tap 4× Hann-windowed sinc estimate including end padding; it is not formal certification. The algorithm-1 streaming limiter remains sample-bounded with cubic estimation and has no lookahead/true-peak guarantee; algorithm 2 limits the reconstructed peak with a 1.5 ms lookahead and a stricter 8× detector, which an independent 32× 128-tap reference holds under the ceiling for program-like material (not formal certification; full-band white noise can still read about 0.15 dB high); the final processed sample ceiling is reapplied after level matching and dither, while original/bypass paths preserve the source. `limiter.targetLufs` is metadata only; low-level rendering does not automatically normalize to a loudness target. Simple tone changes reach the live chain without POST normalization. Explicit **Set target loudness** requests up to eight measurement renders of the export parameters (no preview render), estimates the compressed output response with a bracketed secant update, adjusts input gain within ±36 dB, and accepts a result within ±0.2 LU of the target only when the reconstructed peak estimate is no more than 0.2 dB above the selected ceiling. Otherwise it reports a failure. It retains the current EQ, dynamics, saturation, stereo and other settings; changing Simple/Advanced views does not normalize or replace them. Platform compliance remains unavailable. `dynamicRangeDb` is crest factor using peak and stereo-average RMS with a 1 dB floor, not EBU LRA or a standardized DR score. Correlation uses normalized cross-energy without mean subtraction; low-bass correlation filters at 110 Hz. `clippingSamples` counts frames where either channel reaches magnitude 0.9999. DC fields report the dB of the absolute channel mean. These remain diagnostic measurements. Independent comparison fixtures and limits are tracked in [architecture](architecture.md) and [tasks](tasks.md).
