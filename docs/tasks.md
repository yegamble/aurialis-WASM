### Supported-control coverage

The signal matrix in `wasm/dsp/control_matrix_test.go` changes one field at a time on an active fixture, requires a finite sample difference, and separately checks disabled/inactive behavior and reset/state isolation. The compiled parity fixture runs both sides of each pair at 44.1, 48 and 96 kHz: 42 pairs × 2 states × 3 rates plus 15 base fixtures = 267 native/WASM fixtures. This proves those tested mathematical paths agree; it does not certify hardware emulation or every possible input.

| Group | Independent active pairs | Additional boundary or no-op coverage |
|---|---|---|
| Input gain | 1 | Neutral/reset state and source preservation |
| Five-band EQ | 24: each band's gain/frequency/Q/enabled, global bypass, low/high shelf and high-pass types | High-pass frequency response at 8/16/44.1/48/96/192 kHz; zero-gain frequency/Q behavior; source-rate frequency limits |
| Compressor | 7: enabled, threshold, ratio, attack, release, knee, makeup | Ratio-one and disabled-stage no-op behavior |
| Saturation | 4: enabled, drive, Thick and Crisp versus Warm | Disabled-stage no-op behavior |
| Stereo | 3: enabled, width, mono-bass | Mono input remains unchanged when width changes |
| Sample limiter | 3: enabled, ceiling, release | Below-threshold and disabled behavior; true-peak certification remains unavailable |

Simple directions are complete presets built from neutral defaults rather than prior settings. The 36 genre/tone combinations are tested at 0/50/100 intensity after interleaved other selections, preventing repeated Apply from accumulating gain or EQ.

Browser-boundary tests check that individual persisted fields map to the native schema without mutating source settings, that unavailable repair/true-peak controls reject rather than disappear silently, that concurrent previews serialize, and that cancelled work cannot initialize or commit the engine. Simple normalization and A/B monitor regressions have separate tests. Final browser checks must still exercise actual interactions and output; this matrix is not a substitute for them.

### Finite-capacity execution checkpoint

The representative native HTTP probes used 48 kHz stereo input. The 180-second probe retained all 8,640,000 frames and returned 69,120,044-byte canonical float WAV. The 300-second probe retained all 14,400,000 frames and returned 115,200,044 bytes; re-uploading that canonical WAV produced a bit-identical canonical round-trip. These are actual bounded requests, not estimates or a general long-session guarantee.

For the isolated five-minute render plus canonical re-upload, observed maximum resident set size was 495,173,632 bytes (472.2 MiB) and peak memory footprint was 636,453,944 bytes (607.0 MiB). The configured 256 MiB job reservation is not an RSS cap. These observations do not establish a universal 1 GiB process limit or browser/album memory behavior. Longer songs, high sample rates and simultaneous browser/native allocations remain constrained by the documented frame, byte and cache limits.
