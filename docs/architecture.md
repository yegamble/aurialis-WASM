# Aurialis-WASM architecture

This describes current implementation boundaries. [`AGENTS.md`](../AGENTS.md) and [`docs/tasks.md`](tasks.md) retain the full product requirements. Implementation on a branch is not verified delivery or a merge to main.

## Build and serving

`pnpm run build:binary` runs `scripts/build.sh`: compile `wasm/dsp` for `js/wasm`, copy the matching Go `wasm_exec.js`, run the Next.js static export and `scripts/sync-webui.mjs`, then compile `cmd/aurialis`. `internal/webui` embeds generated assets with `//go:embed all:embedded`. The native executable serves HTTP APIs and the frontend without Node at runtime.

`pnpm run test:binary` runs the executable from an empty directory, preventing source-tree assets from masking missing embedded files. The host serves embedded assets only; source-tree output cannot replace the embedded application. Generated assets are not committed, so a fresh `build:binary` is required for a usable application. Dynamic route IDs resolve to static exported shells and browser state supplies the project.

The default bind address is `127.0.0.1:8080`. The middleware emits COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, CSP, nosniff and frame denial headers. Host/Origin and Fetch Metadata checks protect localhost; these checks are not a remote multi-user authentication system.

## Actual browser audio path

1. Home accepts PCM WAV files up to 128 MiB plus the 44-byte canonical header and 16,777,216 decoded frames. A bounded 64 KiB header preflight checks capacity before the authoritative Go container validation. Import posts source bytes with bypass enabled to `/api/master/render`, validating and reconstructing canonical 32-bit float WAV using Go.
2. The canonical source Blob is stored in IndexedDB. Project metadata/settings use localStorage; storage failures display a warning and preserve an in-memory source for the session. Missing source audio blocks rendering/export and requires upload again. Home navigation/replacement, source preparation, export-dialog dismissal and album rendering use abortable requests so stale work cannot commit after cancellation.
3. Advanced settings are independent state fields. **Render preview** loads the real Go WASM module and invokes `aurialisDSPInit`, `aurialisDSPSetParams`, `aurialisDSPReset` and `aurialisDSPProcessBlock` over the decoded source. It processes complete buffers before playback, serializes WASM preview work and yields during long renders; navigation cancels the pending preview. MasterView is keyed by resolved track ID, ensuring track changes remount it and invoke render-abort cleanup. A selects original source and B selects the processed buffer; editing settings invalidates B.
4. Export posts the actual source and latest parameters to the native Go render API. It preserves sample rate and frame count and returns 16/24-bit PCM or 32-bit float WAV. The shared pure-Go engine is `internal/audio/dsp`; frontend code converts parameters and encodes/decodes browser audio rather than maintaining an alternate DSP chain.

Simple direction mapping always starts from a neutral complete preset, so prior selections and repeated Apply cannot accumulate settings. It measures the proposed settings through the native API, then renders the exact resulting immutable settings through WASM. Changing its genre, tone, intensity or target invalidates both processed playback and Simple export until Apply succeeds again; changing mode/direction or leaving the page cancels pending normalization and preview. Advanced mode can export current settings without rendering a preview first.

The transport supports play/pause, seek, volume and RMS-based A/B attenuation of the louder buffer. Position, playing state and effective monitor gain are preserved during source swaps. Continuous real-time DSP remains outstanding. The production preview does not implement an AudioWorklet/SharedArrayBuffer streaming bridge. The packaged browser runtime is `/wasm/wasm_exec.js`; isolation headers alone do not prove real-time integration.

## DSP and measurement boundaries

The Go engine implements gain, five EQ bands, compressor, saturation, stereo processing and limiting. Compressor topology names currently share the same mathematics; the saturation characters are heuristic models. Mono-bass uses side-channel filtering that preserves the mono mid signal; it is not a validated textbook Linkwitz–Riley crossover. Current mathematical and safety tests establish particular transfer behaviors; they do not certify named hardware emulations, a Waves-equivalent chain, formal ITU/EBU conformance, or anti-aliasing performance. Limiter safety remains a sample-domain boundary; its streaming cubic interpolation is separate from the offline peak meter.

Browser metrics are measured sample peak in dBFS, RMS and crest factor. The API meter uses independent BS.1770/DeMan K-weighting, 400 ms windows at 75% overlap, an absolute −70 LUFS gate followed by a relative −10 LU gate, and a trailing three-second short-term interval. Shorter clips use their available duration for diagnostic reporting. The offline peak estimate uses a 49-tap, 4× Hann-windowed sinc interpolator with end padding. Fifteen external FFmpeg comparisons at 44.1/48/96 kHz reported at most 0.0542 LU loudness error and 0.0312 dB peak error for the selected fixtures; abrupt 8 kHz boundaries can differ by 0.58 dB. These are bounded fixture comparisons, not all-waveform guarantees or formal standards certification; the limiter has no validated true-peak/lookahead guarantee. The low-level `targetLufs` field remains metadata: Advanced rendering performs no implicit gain calibration. Simple mode explicitly measures output and adjusts an immutable input-gain snapshot toward its selected target, with bounded iterations and failure reporting when the target cannot be reached. See [`api.md`](api.md) for field limits. `pnpm run test:wasm` runs real compiled WASM/native parity fixtures; `pnpm run test:meters` runs independent FFmpeg meter comparisons. Both are wired into CI.

## Jobs, uploads and lifetime

`internal/server` handles bounded multipart requests and decodes audio in memory. User-supplied filenames do not become disk paths. Decoders accept mono/stereo PCM/float WAV and 16-bit PCM AIFF, rejecting multichannel input. AIFC and compressed formats are rejected; recognized compressed signatures are not evidence of decoders. Reconstruction emits new WAV samples and discards metadata. Signature checks inspect headers/metadata/trailers, never arbitrary PCM bytes; this is not steganography detection. Finite float-WAV headroom survives decode/export, while non-finite values are sanitized and integer exports clamp to full scale.

`internal/jobs` owns the experimental Deep-analysis and heuristic separation queues and cancellation. These APIs are not connected to enabled product workflows. Multipart bodies have a hard 129 MiB cap, audio files a 128 MiB plus canonical-header cap, and decoding a 16,777,216-frame cap. One expensive POST is admitted at a time; another receives retryable 503 before body allocation. Job decoded input, float output, encoded artifacts and scratch reservations are bounded at 256 MiB, retention at 64 records, and worker count at four. These are finite working/admission budgets, not a total RSS guarantee. Isolated 3/5-minute native render and canonical re-upload measurements are recorded in the task tracker; full browser/album-scale and arbitrary concurrency behavior require separate evidence. Jobs time out after two minutes; terminal artifacts expire after 15 minutes. See [`api.md`](api.md).

## UI and remaining product scope

Next.js 16 App Router, React 19, strict TypeScript and Tailwind v4 provide the warm editorial design. Production icons are custom inline SVGs. Shared controls and the shell support mobile and desktop layouts; automated axe and overflow checks are evidence for tested routes and interactions, not blanket WCAG certification.

The production store starts empty and discards legacy example projects, simulated scripts/stems and stale release scores. Simple mastering measures output before selecting normalized settings. Profile mastering applies one of five static presets; musical analysis, automation and AI repair remain open. Smart Split exposes an unavailable state without fabricated artifacts. Albums measure and render tracks sequentially toward −14 LUFS, producing individual 24-bit PCM WAV downloads in a 128 MiB session cache while retaining original sources. Cache keys include the track IDs, order and processing settings; settings/sequence changes or leaving the page invalidate those artifacts. Sequence controls are locked while rendering. There is no ZIP or persistent mastered-artifact store. Reference direction explicitly blends project EQ settings; both curves use one logarithmic frequency/gain scale while respecting each track’s sample-rate bandwidth. Saved metrics identify whether they describe source audio or an album render. Spectral matching remains open. Release diagnostics measure native rendered output against working targets and invalidate results on track/settings changes; they do not certify platform delivery.

Shared Tailwind button variants, dialog surfaces, control groups and module disclosures provide ordinary layout and interaction styling. The shared `DSPModule` uses native disclosures for keyboard and touch access; five-band EQ has direct pointer/keyboard interaction and labeled form alternatives. Global CSS retains design tokens, base rules and specialized audio/artwork styling. Inline SVGs remain the only production icon source. See [tasks](tasks.md) for final-checkpoint verification and outstanding scope.
