## Measured source features

`POST /api/analyze/features` (alias `/analyze/features`) accepts one multipart `file` through the existing reconstruction and admission path. Options and query parameters are rejected. It returns the existing **202** job envelope with `kind: "analyze_features"`. Health advertises `featureAnalysisMethod` and `featureAnalysisVersion`. Poll `GET /api/jobs/{jobId}?wait=1`; the native status values are `queued`, `running`, `done`, `failed` and `cancelled`. A `done` response includes `features`, not a mastering script. `DELETE /api/jobs/{jobId}` cancels and releases retained summaries. Failed delivery of the admission response cancels that job.

`features.version` is `"1.0"`. Its `source` contains `pcmHash`, `sampleRate` and `frames`. SHA-256 covers little-endian uint32 sample rate, uint32 channel count 2, uint64 frame count, then interleaved little-endian L/R Float32 bits. This binds measurements to reconstructed stereo PCM and layout.

The five bands are 20–120, 120–500, 500–2000, 2000–6000 and 6000–20000 Hz. Each reports `lowHz`, `highHz`, `usableHighHz`, `bandwidthHz`, `powerDb`, `densityDbPerHz` and `valid`; unavailable bandwidth is explicit. Power is stereo-averaged mean square; unequal band widths are not interchangeable tonal targets. DC is excluded from spectral diagnostics while original RMS/stereo energy retains it. Normalized Hann FFT frames (1024–16384 samples, chosen by rate) use 75% overlap and padded endpoints with constant squared-window coverage, then aggregate into one-second windows at quarter-second hops. Raw RMS/stereo windows use original samples independently of spectral weighting. Very short sources use their available duration.

`frames` contains `centerFrame`, `rmsDb`, `centroidHz`, `sideMidDb` and `crestDb`. `windowCrestPercentiles` holds p10/p50/p90. `sibilanceRatioDb` is 6–12 kHz power relative to usable power at or above 20 Hz; it is neither a sibilance diagnosis nor a crest factor. Finite floors/conventions and bandwidth warnings accompany low-information signals.

`sections` partition the exact source-frame interval with neutral `Section N` names, `roleHint: "unknown"` and `confidence`. Confidence is a bounded novelty-strength heuristic, not a calibrated musical-role probability. Boundaries require eight-second spacing on sufficiently long sources; silence, constant fixtures and short clips can have one section. No EQ proposal, processing move, Verse/Chorus classification or trained-model claim is returned.

The job reserves decoded input plus 16 MiB analysis headroom; retained feature arrays are charged conservatively until cancellation/expiration. GET snapshots deep-copy mutable feature slices. Existing 256 MiB/64-job limits, worker timeout, retention, Host/Origin and upload bounds apply. Browser source analysis releases its admitted job after copying successful diagnostics, and deletes a known admitted job after Cancel. Cancel detaches the UI immediately even when the admission response is held; bounded transport failure falls back to server timeout/retention.

## DSP compatibility and capability foundation

The optional `params.algorithmVersion` accepts omitted/zero/one as unchanged algorithm 1; null, fractional, negative and unimplemented values are rejected. The sonic algorithm is independent of the numeric control ABI. Existing 81-value controls remain supported. The integrated browser negotiates ABI 2 and publishes 82 values in a 672-byte shared packet, appending explicit algorithm ID 1 through its separate buffer/setter. It does not enable algorithm 2.

Both WASM modules export `aurialis_control_count(abi)` (81 for 1, 82 for 2, zero otherwise), `aurialis_algorithm_supported(version)` (one only for explicit algorithm 1), `aurialis_latency_frames()` and `aurialis_live_drain()`. The appended interface uses `aurialis_control_buffer_v2` and `aurialis_set_controls_v2(count)`; invalid length/version rejects atomically. The worklet requires implemented algorithm 1, matching current count and zero buffered latency before playing. Native `LatencyFrames()` and `Drain()` currently return zero; drain preserves destination contents and does not synthesize an IIR-decay extension. Transport alignment and filter phase are separate from buffered DSP latency.

## ScriptV2 foundation

Script schema `2.0`, schedule ABI `1` and sonic algorithm `1` are independent versions. The integrated Deep editor uses these interfaces for explicit source-bound Apply; their presence alone does not certify browser render deadlines.

The bounded foundation passed local native/API/compiled-WASI verification and the complete existing-UI browser regression. `POST /api/analyze/deep` and `/analyze/deep` accept multipart `file`, optional `profile` and `scriptVersion=2.0`. Omitting the version retains the legacy job. Version 2 returns a 202 job with `kind: "analyze_deep_v2"`; a successful snapshot contains `scriptV2`. Existing polling, DELETE, timeout, admission and source-upload limits apply. Failed admission-response delivery cancels the admitted job. The job reserves decoded input plus 32 MiB headroom; retained scripts are charged at 2 MiB and snapshots deep-copy editable arrays.

The measured proposal uses neutral sections and a regularized fit against a smooth spectral trend, with uncertainty findings. It is a conservative heuristic, not musical-role or instrument recognition. Its explicit baseline uses algorithm 1, disabled repair, the sample-peak limiter and the existing generic Optical compressor. It adds no hidden loudness normalization.

The script contains `version`, `source`, `revision`, canonical `profile`, `summary`, `sections`, `moves`, `findings`, `chainParams` and `beforeMetrics`. `source` uses the canonical PCM identity documented above. Sections partition the complete source using integer `startFrame`/`endFrame` values and neutral `roleHint: "unknown"`. Revisions are integers from 1 through 2^53−1. Unknown, duplicate, case-aliased, missing required or null JSON fields are rejected; JSON is capped at 2 MiB. There are at most 128 sections, 128 findings and 128 moves, each with 2–256 strictly increasing points. A move contains a unique `id`, valid `sectionId`, bounded `reason`, `target`, `operation` (`absolute` or `add`), `points` (`frame`, `value`), `fadeFrames` and `muted`. Same-target intervals cannot overlap. Intervals are half-open; fades fit half the interval and at most 100 ms.

| Target | Absolute range | Evaluation |
| --- | --- | --- |
| `inputGainDb` | −36…36 dB | Every sample before processing |
| `eq.0.gainDb` through `eq.4.gainDb` | −24…24 dB | Held cells; maximum 0.1 dB parameter variation |
| `compressor.thresholdDb` | −80…12 dB | Held cells; maximum 0.1 dB variation |
| `compressor.ratio` | 1…100 | Held cells; maximum 0.01 variation |
| `saturation.amount` | 0…100 | Held cells; maximum 0.1 percentage-point variation |
| `stereo.widthPct` | 0…200 | Every sample at the stereo stage |

An `add` move is resolved once against the explicit baseline. Gain and width use an exact rational source/device clock. Other targets use the absolute device lattice `max(1, floor(deviceRate / 1000))`; curves and fades exceeding the declared cell error are rejected with an instruction to extend fades or reduce changes. These are parameter-error limits, not universal acoustic tolerances. Automation does not enable modules; bypass and disabled stereo retain their normal semantics. Repair targets and enabled repair/true-peak limiter baselines are rejected by ScriptV2 validation.

`POST /api/master/render` and `/master/render` accept a multipart text field `script` containing the complete ScriptV2, mutually exclusive with `params` and `profile`. Native rendering hashes actual reconstructed PCM and rejects a different source, then runs the common evaluator at the source rate. Existing WAV/JSON output and bit-depth options apply; 16/24-bit output selects corresponding dither. Invalid scripts or identities return 400, oversized fields 413 and cancellation 408.

`POST /api/automation/compile?deviceRate=48000` accepts only `application/json` ScriptV2, up to 2 MiB. The optional integer rate defaults to the source rate; both rates must be 8000–192000 Hz. No root alias exists. Its 200 JSON response contains `version: "1.0"`, `source`, `revision`, `deviceRate`, `quantumFrames`, `baseline`, numeric `moves`, `targets` and **`sourceVerified: false`**. It validates declared identity and layout without receiving audio; the host must bind authoritative actual-source metadata before playback. Compilation shares the single POST admission slot and 60-second request timeout. Invalid content type/query/script returns 400, excess body 413, cancellation 408 and busy admission 503.

The numeric WASM interface advertises `aurialis_schedule_abi() == 1`. Its 11-value source buffer contains ABI 1, source rate, frame count and eight big-endian SHA-256 uint32 words. `aurialis_schedule_bind_source` accepts a new host-supplied identity only while detached; binding the same identity is idempotent even while attached. It does not hash browser PCM. `aurialis_schedule_begin(revision, count, deviceRate)` reads the separate 82-value algorithm-1 baseline and stages an inactive slot. Each `aurialis_schedule_stage_move(index)` call copies at most 256 points from the 516-value move buffer: target index, point count, fade frames, muted 0/1, then frame/value pairs. `aurialis_schedule_commit` publishes the complete baseline and revision atomically; `aurialis_schedule_revision` acknowledges it. Stale or invalid publication preserves the active revision. Static JSON/numeric setters and band edits reject while attached. The integrated browser stages them through the publication protocol below; retained kernel and browser acceptance evidence remain separate.

Bind before the source starts: every processed device frame then advances an independent rational source clock, including static/bypassed playback. First Apply and later revisions inherit its exact phase. Hosts submit no processing frames during hold/pause. Initial or changed-source binding starts phase zero without resetting DSP history; same-source binding preserves both. `aurialis_schedule_seek` works while detached or attached, reconstructs source-zero phase and resets DSP history; invalid seeks preserve state. `aurialis_schedule_set_looping` works in either state and retains fractional overshoot without resetting DSP history at wraps. `aurialis_schedule_detach` restores the explicit baseline while preserving phase for later reapply. `aurialis_live_reset` seeks zero while retaining bound identity, loop policy, attachment and accepted revision. Binding a different source requires detach. No ABI signature changed for this correction.

This drains the existing alignment ring, not an invented DSP-decay tail. Go owns rational phase, envelopes and loop evaluation; TypeScript neither evaluates envelopes nor resamples audio. Pause submits no frames, seek resets the Go history/source epoch, and native AudioBufferSource resampling supplies actual device input. ## Measured Reference proposals

`POST /api/analyze/reference` accepts multipart audio parts `source` and `reference`, optional `params` (up to 64 KiB, existing DSP validation, native defaults when omitted) and optional `options` (up to 2048 bytes). There is no root alias. Both files pass the in-memory CDR boundary and retain raw canonical source identities. The combined multipart body shares the existing 129 MiB maximum, including metadata and boundaries; adding a reference does not double that limit. Each decoded file retains the 16,777,216-frame bound. Query parameters, duplicate/unknown parts and invalid file dispositions are rejected.

Options default to `amount: 0.5`, `protectBelowHz: 120`, `includeWidth: false` when the field is omitted. Supplied options require finite `amount` in 0…1 and `protectBelowHz` equal to 0 or 120; optional `includeWidth` is boolean. Unknown, duplicate, case-aliased, missing required or null option fields are rejected. The browser's 0…100% amount control converts to the API fraction.

Admission returns 202 with `kind: "analyze_reference"`; poll the existing job route for `referenceProposal`. Existing DELETE/expiry, authority/Origin checks, single POST admission and two-minute worker timeout apply. Both decoded inputs are reserved together under the manager lock: `source.frames × 8 + reference.frames × 8 + 32 MiB`, within the shared 256 MiB job budget and 64-record limit. Results are bounded/charged at 32 KiB, snapshots deep-copy warnings/optional width metadata, and cancellation clears the retained proposal. These are working/admission bounds, not a process RSS guarantee. Failed admission-response delivery cancels the job.

`referenceProposal.version` is `"1.0"`; `sourceSpectrum` is **`"baseline_rendered"`**. `source` and `reference` identify the raw canonical PCM. `baseline` is the exact submitted chain; `params` is its proposed replacement. `options`, five `bands`, residual/guard diagnostics, optional `width` and `warnings` describe the estimate. Each band reports `lowHz`, `highHz`, `sourceDensityDb`, `referenceDensityDb`, `targetDeltaDb`, `predictedDeltaDb` and `included`. Common edges are 20/120/500/2000/6000/20000 Hz clipped to the lower Nyquist. Unavailable or insufficient-energy bands are excluded; fewer than three audible common bands produces no tonal correction. Spectra remove DC and use normalized overlapping Hann powers; source measurements include its complete baseline chain, while the reference uses original reconstructed audio. Overall common-band level is normalized for tonal comparison; input gain and loudness targets remain unchanged.

The regularized fit changes only enabled non-high-pass EQ gains, by at most ±3 dB per knob, while numerically checking the actual summed TPT response for at most 3 dB added positive peak. Band frequencies, Q, filter types, enable flags and unrelated chain parameters are preserved. Amount zero retains the exact baseline; bypass/Original and disabled modules remain authoritative. The optional 120 Hz protection checks predicted 20–120 Hz response and complete rendered band-energy change within 0.25 dB. These numerical/source-specific checks are not hardware certification.

Optional width is limited to ±20 percentage points times amount, within 0…200%; it never enables stereo or invents absent stereo energy. Rendered correlation must remain at least 0.1 for a changed width. Width diagnostics include before/after width, Side/Mid energy, correlation, sample peak, `applied` and `reason`.

Every final candidate is rendered through the complete chain. Up to eight bounded attempts halve only the permitted EQ/width deltas; accepted output must not worsen the level-normalized common-band mismatch beyond a 1e-9 dB arithmetic allowance, and must meet enabled bass protection. Exact baseline is the fallback. Erased audible output cannot earn a better score; its internal invalid-candidate sentinel is never retained in JSON. `beforeOutputResidualDb`/`afterOutputResidualDb` measure actual full-rendered mismatch. The separate `beforeResidualDb`/`fitResidualDb` describe the linear EQ-contour fitting objective and must not be presented as final output quality. Predicted boost/protection and `remeasuredProtectedDeltaDb` are diagnostics; `protectionVerified: false` can identify an unchanged baseline. Final LUFS, reconstructed peak and perceptual similarity remain separate checks.

The browser verifies both loaded canonical Blobs against SHA-256 source receipts before and after analysis, validates exact baseline/options and permits only bounded EQ/opt-in-width deltas. Apply uses a complete-record compare-and-swap for the reviewed source/reference and current settings. Amount changes and repeated Apply use the same original session baseline. ## Security and resource contract

The executable binds only to loopback IPs (default `127.0.0.1:8080`). `AURIALIS_ADDR` takes precedence over `PORT`, then `-addr`; a numeric `PORT` becomes `127.0.0.1:<port>`. The request Host must match an allowed local authority and the actual port. A supplied Origin must be HTTP with the same authority; `null` is rejected. Fetch Metadata permits only `none` or `same-origin` when supplied. Rejections return 403 JSON. These checks do not provide remote authentication.

Responses carry COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, and a CSP restricted to same-origin assets with hashes for the embedded bootstrap scripts. WASM uses `application/wasm`. Browser fonts are self-hosted. Permissions-Policy disables unused device access; WAV download responses also carry a sandbox CSP.

Multipart bodies are capped at **129 MiB including overhead**. The audio file is capped at **134,217,772 bytes** (a maximum stereo-float WAV including its 44-byte header); the browser uses the same file-byte cap, allowing 128 MiB of stereo-float samples plus the canonical header. `-max-upload-bytes` / `MAX_UPLOAD_BYTES_OVERRIDE` can lower the request cap, never increase it. Decoding permits **16,777,216 frames**: about 349.5 seconds at 48 kHz or 174.8 seconds at 96 kHz; byte limits can shorten this. Canonical float re-upload fits the multipart limit.

One expensive POST upload/render is admitted at a time. Another receives **503 busy**, with `Retry-After: 1`, before its body is read. Worker jobs reserve decoded input, float output, encoded artifacts and scratch headroom within **256 MiB**, retain at most **64 jobs**, and return **503 queue_full** when admission fails. Automatic mode starts the smaller of two workers or the available logical CPU count; explicit worker counts are capped at four. The reservation is a job working budget, not a process RSS guarantee. A separate single-request frame/body bound limits synchronous scratch. Representative native 3/5-minute tests and observed memory belong in the task tracker; browser and arbitrary workload memory are not certified by those probes. Worker timeout is two minutes; terminal artifacts expire after 15 minutes, checked every minute. Cancellation clears artifacts while preserving an idempotent status receipt for up to 15 minutes. Under record pressure, an affordable new admission may evict the oldest canceled receipt only after its worker reservation reaches zero; equal timestamps use stable ID order. Active/canceled-but-unsettled jobs and unclaimed results cannot be evicted this way. An evicted receipt returns 404 on GET/DELETE. Invalid or unaffordable demand cannot trigger pressure eviction.

Uploaded names are validated and never used for host disk writes. Parsing/decoding stays in bounded memory. Only mono/stereo input is supported; multichannel input is rejected. Supported inputs are WAV PCM 8/16/24/32-bit integer or 32-bit float, and 16-bit PCM AIFF. AIFC and compressed MP3/FLAC/OGG/M4A/AAC decoding are unsupported. WAV checks include declared RIFF length, alignment, byte rate, chunk bounds, duplicate chunks and whole frames. Reconstruction creates new samples without metadata. Executable/archive/script signatures are inspected in headers, metadata and outside-container trailers, not arbitrary PCM bytes. Legitimate sample bytes can match those signatures. Reconstruction is the audio-only boundary; this is not PCM steganography detection or a universal malicious-content guarantee.

Errors use JSON with `error`, `detail` and numeric `status`. Malformed fields/container/params return 400, oversized requests 413, rejected authority/origin 403, missing resources 404, admission failures 503, and encoding failures 500.

### Rendering

Send `multipart/form-data` with required `file` and optional fields:

- `profile`: `Warm Analog`, `Punchy Commercial`, `Dynamic & Open`, `Vocal Forward`, `Bass Heavy`; compatibility aliases include `indie_warmth`, `modern_pop_polish`, `pop_punk_air`, `hip_hop_low_end`, `metal_wall`.
- `params`: JSON overlay on default/profile DSP parameters. Unknown fields, nulls, trailing JSON, invalid enums, non-finite/out-of-range values and non-five-element `bands` arrays return 400. EQ band types include `low_shelf`, `peaking`, `high_shelf`, and actual `high_pass` processing. Parameters include `bypass`, `abOriginal`, `loudnessMatchAb`, `inputGainDb`, `eqEnabled`, `bands`, `compressor`, `saturation`, `stereo`, `limiter`, `repair`, `deHarsh`, `multiband`, `ditherBits`. Field presence does not guarantee every advertised analog topology has distinct behavior.
- `bitDepth`: `16`, `24` (default), or `32`; other values return 400. 16/24-bit PCM receives TPDF dither and clamps to integer full scale; 32-bit float decode/export preserves finite headroom above ±1. NaN and infinity are sanitized to zero. Processing can change source levels; bypassed float round-trips preserve headroom.
- `format=json`, or `Accept: application/json`: return `status`, `sampleRate`, `frames`, `duration`, `bitDepth`, `params`, `beforeMetrics`, `afterMetrics` instead of audio.

Supplied `bands` arrays require exactly five complete EQ objects; supplied `multiband.bands` arrays require exactly three complete dynamics objects. Case variants such as `Bands`, `Multiband` and nested `BANDS` receive the same array validation. Every differently cased alias supplied in one object must satisfy those count and completeness checks. Numeric ranges are validated on the final decoded settings after alias resolution. Identical duplicate JSON keys retain the decoder's existing last-value behavior. Rejected settings return 400 without applying the update.

WAV output uses `Content-Type: audio/wav`, `Content-Disposition: attachment; filename="aurialis-mastered.wav"` and compatibility headers `X-Aurialis-Before-LUFS`, `X-Aurialis-After-LUFS`, `X-Aurialis-After-Peak-dBTP`. Rendering preserves the uploaded sample rate and frame count. Metric fields are `integratedLufs`, `shortTermLufs`, `truePeakDbtp`, `samplePeakDbfs`, `dynamicRangeDb`, `correlation`, `lowBassCorrelation`, `dcLeftDbfs`, `dcRightDbfs`, `clippingSamples`, `gainReductionDb`; see the measurement limitations below.

For an audio response with `params.bypass=true` and `bitDepth=32`, the server additionally sends `X-Aurialis-Source-Metrics`: at most 4096 bytes of JSON containing `sourceIdentity`, `sampleRate`, `frames`, `duration`, `beforeMetrics` and `afterMetrics`. The identity has `pcmHash`, `sampleRate` and `frames`, using exactly the canonical SHA-256 byte layout described under measured source features. It is computed without FFT analysis and remains stable through canonical float-WAV reconstruction. Both metric objects describe the reconstructed source and use the schema above. The server measures this bypass source once and reuses its decoded samples instead of running the enabled-DSP render path. WAV responses declare their exact `Content-Length`. This changes neither CDR validation nor request, frame, admission or timeout limits.

The browser import uses this single response instead of separate measurement and reconstruction POSTs. It rejects missing, oversized or invalid measurement headers, cancels an unusable response body, checks canonical byte size (`44 + frames × 8`), then validates the decoded sample rate and frame count against the header. These checks describe transfer consistency; they do not replace the authoritative native decoder.

```bash
curl --fail-with-body http://127.0.0.1:8080/api/master/render \
  -F file=@source.wav -F 'params={"inputGainDb":-6}' \
  -F bitDepth=24 -o mastered.wav

curl --fail-with-body http://127.0.0.1:8080/api/master/render \
  -F file=@source.wav -F 'params={"bypass":true}' -F format=json
```

## Measurement limits and verification

Live playback meters are computed from actual audible blocks: sample peak dBFS, stereo RMS, crest factor and correlation. The 4096-point spectrum averages L/R power and describes the monitored processed/original selection. Measurements arrive at up to 20 Hz; animation-frame interpolation changes the drawn transition between measured traces, not the underlying measurements. These values are separate from full-track API diagnostics. Release review bypass-measures the exact selected encoded WAV; an attached Deep script supplies the acknowledged applied settings. The API meter uses BS.1770/DeMan K-weighting with 400 ms windows and 75% overlap, absolute −70 LUFS and relative −10 LU gates, and a trailing three-second short-term interval. Short clips use the available duration, which is a diagnostic approximation to standard-duration reporting. Silence reports a finite −70 LUFS floor. Offline `truePeakDbtp` uses a finite 49-tap 4× Hann-windowed sinc estimate including end padding; it is not formal certification. The streaming limiter remains sample-bounded with cubic estimation and has no validated lookahead/true-peak guarantee; the final processed sample ceiling is reapplied after level matching and dither, while original/bypass paths preserve the source. `limiter.targetLufs` is metadata only; low-level rendering does not automatically normalize to a loudness target. Simple tone changes reach the live chain without POST normalization. Explicit **Set target loudness** prepares an offline preview and requests up to eight measurement renders, estimates the compressed output response with a bracketed secant update, adjusts input gain within ±36 dB, and accepts a result within ±0.2 LU of the target only when the reconstructed peak estimate is no more than 0.2 dB above the selected ceiling. Otherwise it reports a failure. It retains the current EQ, dynamics, saturation, stereo and other settings; changing Simple/Advanced views does not normalize or replace them. Platform compliance remains unavailable. `dynamicRangeDb` is crest factor using peak and stereo-average RMS with a 1 dB floor, not EBU LRA or a standardized DR score. Correlation uses normalized cross-energy without mean subtraction; low-bass correlation filters at 110 Hz. `clippingSamples` counts frames where either channel reaches magnitude 0.9999. DC fields report the dB of the absolute channel mean. These remain diagnostic measurements. Independent comparison fixtures and limits are tracked in [architecture](architecture.md) and [tasks](tasks.md).
